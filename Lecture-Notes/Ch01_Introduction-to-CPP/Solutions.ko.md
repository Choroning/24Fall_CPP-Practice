## 교재 이론 문제

**교재:** 1장 연습문제의 이론 문제 중 짝수 번 문항

### 이론 문제 2

**문제:** 프로그래밍 언어와 컴파일러에 관한 네 설명 중 틀린 것을 고르라.

**정답:** ④

기계어는 0과 1로 이루어진 이진 코드이므로 사람이 읽고 수정하기 어렵고, CPU 아키텍처마다 달라 기계 종속적이다. 기계어로 프로그램을 작성하면 생산성과 이식성이 모두 낮으므로, 기계어를 익혀 프로그램을 작성하는 것은 좋은 개발자가 되는 지름길이 아니다. 오늘날의 프로그램은 대부분 고급 언어로 작성하고 컴파일러가 기계어로 번역한다([1장 1.2절](Concepts_Lecture.ko.md#12-프로그래밍-언어)).

나머지 설명은 옳다.

- ① 고급 언어는 `if`, `while`, `class`처럼 자연어에 가까운 문법을 쓰므로 사람이 이해하기 가장 쉽다.
- ② CPU가 직접 실행할 수 있는 것은 기계어뿐이다. 어셈블리어와 고급 언어로 작성한 프로그램은 실행 전에 기계어로 번역되어야 한다.
- ③ 고급 언어 프로그램을 기계어로 번역하는 프로그램이 컴파일러이다([1장 1.3절](Concepts_Lecture.ko.md#13-컴파일러)).

### 이론 문제 4

**문제:** Java, C, C++, C# 중 객체 지향 언어가 아닌 것을 고르라.

**정답:** ②

C는 실행할 절차를 함수와 명령문의 순서로 나열하는 절차 지향 언어이며, 클래스, 상속, 접근 지정 같은 객체 지향 기능이 없다. Java, C++, C#은 클래스로 객체를 정의하고 캡슐화, 상속, 다형성을 지원하는 객체 지향 언어이다. C++은 C에 객체 지향 기능을 더한 언어이며([1장 2.1절](Concepts_Lecture.ko.md#21-역사)), 절차적 프로그래밍과 제네릭 프로그래밍도 함께 지원한다.

### 이론 문제 6

**문제:** 상속, 흐름도, 캡슐화, 다형성 중 객체 지향 개념이 아닌 것을 고르라.

**정답:** ②

객체 지향 프로그래밍의 세 가지 기둥은 캡슐화, 상속, 다형성이다([1장 2.3절](Concepts_Lecture.ko.md#23-객체-지향-프로그래밍)). 흐름도(flowchart)는 작업의 실행 순서를 도형과 화살표로 나타낸 그림으로, 흐름도를 설계하고 그 순서대로 명령문을 작성하는 절차 지향 프로그래밍의 설계 도구이다. 객체 지향 프로그래밍은 실행 순서보다 객체들의 상호 관계와 상호 작용을 중심으로 프로그램을 설계한다.

- **캡슐화:** 데이터와 그 데이터를 다루는 함수를 클래스로 묶고, 내부를 외부의 접근으로부터 보호한다.
- **상속:** 기존 클래스의 멤버를 물려받아 새 클래스를 정의한다.
- **다형성:** 같은 이름의 연산자나 함수가 대상에 따라 다르게 동작한다.

### 이론 문제 8

**문제:** C++이 C 언어의 문법 체계를 이어받아 생긴 문제점을 고르라.

**정답:** ④

C++은 기존 C 프로그램을 그대로 활용할 수 있도록 C와의 호환성을 추구하므로, C처럼 클래스 바깥에 전역 변수와 전역 함수를 선언할 수 있다. `main()`도 클래스에 속하지 않는 전역 함수로 작성해야 한다. 그 결과 모든 데이터와 함수를 클래스 안에 캡슐화한다는 객체 지향의 원칙이 무너지고, 여러 함수가 같은 전역 변수를 고치면서 생기는 부작용(side effect)의 염려가 생긴다([1장 2.5절](Concepts_Lecture.ko.md#25-c-호환성의-대가)).

- ①, ② 개발 과정이나 프로그램 관리의 어려움은 C 문법의 계승에서 직접 생기는 문제가 아니다. C++은 오히려 클래스와 상속으로 코드의 재사용을 쉽게 하여 큰 소프트웨어의 개발과 관리를 돕는다.
- ③ C와의 호환성 덕분에 C++ 프로그램은 C 라이브러리를 그대로 사용할 수 있다. C 표준 라이브러리는 C++ 표준 라이브러리의 일부이며 `<cstring>`, `<cmath>` 같은 헤더로 사용한다([1장 3.1절](Concepts_Lecture.ko.md#31-표준-라이브러리의-구성)).

### 이론 문제 10

**문제:** C++ 표준에 따라 프로그램을 작성할 때 얻는 장점을 고르라.

**정답:** ②

C++ 표준(ISO/IEC 14882)은 언어의 문법과 표준 라이브러리를 정의한다. 표준이 정한 기능만으로 작성한 프로그램은 표준을 따르는 모든 컴파일러(GCC, Clang, MSVC 등)에서 컴파일되고, 운영체제와 컴파일러에 관계없이 같은 실행 결과를 낸다. 이처럼 소스 코드를 다른 플랫폼으로 그대로 옮겨 쓸 수 있는 성질이 호환성(이식성, portability)이다. 반대로 `__cdecl`처럼 특정 컴파일러의 확장 기능을 쓴 프로그램은 그 컴파일러에서만 컴파일된다([1장 2.6절](Concepts_Lecture.ko.md#26-표준-c의-중요성)).

확장성, 실행 성능, 개발 용이성은 표준 준수 여부보다 프로그램의 설계, 컴파일러의 최적화, 개발 도구와 라이브러리에 더 크게 좌우되므로 표준을 따를 때 얻는 고유한 장점이라 하기 어렵다.

### 이론 문제 12

**문제:** 캡슐화, 다형성, 상속성을 각각 TV 객체, `>` 연산자, "메뚜기는 생물이다"라는 문구를 예로 들어 설명하라.

**정답:**

**(1) 캡슐화:** TV 객체는 채널 번호, 음량, 전원 상태 같은 데이터와 채널 변경, 음량 조절, 전원 켜기와 끄기 같은 기능(멤버 함수)을 하나로 묶은 것이다. 사용자는 채널을 바꾸고 싶을 때 채널 버튼만 누르면 되고, 채널이 실제로 바뀌는 내부 구조는 알 필요가 없다. 이처럼 복잡한 내부 구현을 숨기고 간단한 인터페이스만 공개하여 사용을 쉽게 하고 내부 데이터를 외부의 잘못된 접근으로부터 보호하는 것이 캡슐화이다.

**(2) 다형성:** 같은 `>` 연산자도 피연산자의 타입에 따라 다르게 동작한다. `5 > 3`처럼 정수에 쓰면 두 수의 크기를 비교하여 `true`가 되고, `string("Apple") > string("Banana")`처럼 `string` 객체에 쓰면 두 문자열을 사전 순으로 비교하여 `"Apple"`이 `"Banana"`보다 앞이므로 `false`가 된다. 이처럼 하나의 연산자나 함수가 대상에 따라 다른 방식으로 동작하는 것이 다형성이며, `string`의 `>`는 연산자 중복으로 정의된 것이다. 같은 이름으로 여러 타입을 다룰 수 있으므로 코드의 재사용성과 확장성이 높아진다.

**(3) 상속성:** 생물 클래스에 모든 생물이 공통으로 가지는 특성을 정의하고 메뚜기 클래스가 생물 클래스를 상속받으면, 메뚜기 클래스는 생물의 특성을 따로 정의하지 않고도 가지면서 메뚜기만의 특성을 추가로 정의할 수 있다. "메뚜기는 생물이다"처럼 "A는 B이다"가 성립하는 관계가 상속 관계이다. 상속은 코드의 재사용성을 높이고 클래스 사이의 계층 구조를 표현한다.

다음 프로그램은 (2)의 두 비교를 실행한 것이다.

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    cout << (5 > 3) << endl;                                 // 정수의 크기 비교
    cout << (string("Apple") > string("Banana")) << endl;    // 문자열의 사전 순 비교
    return 0;
}
```

**실행 결과:**

```text
1
0
```

`cout`은 `bool` 값 `true`와 `false`를 기본적으로 1과 0으로 출력한다.

> **주의:** `"Apple" > "Banana"`처럼 문자열 리터럴끼리 비교하면 사전 순 비교가 아니라 두 문자 배열의 주소를 비교한다. 그 결과는 정해져 있지 않으며(unspecified), Clang은 `-Wall`에서 "result of comparison against a string literal is unspecified" 경고를 낸다. C++20부터는 배열끼리의 비교 자체가 폐지 예정(deprecated)이다. 문자열을 사전 순으로 비교하려면 `string` 객체로 비교하거나, C 스트링이면 `strcmp()`를 쓴다.

(3)의 관계를 C++ 코드로 나타내면 다음과 같다.

```cpp
#include <iostream>
using namespace std;

class Creature {                   // 생물: 모든 생물이 공통으로 가지는 특성
public:
    void breathe() { cout << "숨을 쉰다" << endl; }
};

class Grasshopper : public Creature {   // 메뚜기는 생물이다
public:
    void jump() { cout << "높이 뛴다" << endl; }
};

int main() {
    Grasshopper g;
    g.breathe();                   // Creature에서 상속받은 멤버 함수
    g.jump();                      // Grasshopper에 추가한 멤버 함수
    return 0;
}
```

**실행 결과:**

```text
숨을 쉰다
높이 뛴다
```

`Grasshopper`에는 `breathe()`를 정의하지 않았지만 `Creature`를 상속받았으므로 `g.breathe()`를 호출할 수 있다. 상속은 8장에서 자세히 다룬다.

### 이론 문제 14

**문제:** `delete` 연산자, 함수 중복, 참조에 의한 호출, 타입 변환 중 C++이 C 언어에 새로 추가한 것이 아닌 것을 고르라.

**정답:** ④

타입 변환은 C 언어에도 있던 기능이다. C에서도 `int`와 `double`을 섞어 계산할 때 자동으로 일어나는 암시적 타입 변환과, `(double)n`처럼 캐스트 연산자로 지정하는 명시적 타입 변환을 모두 쓸 수 있다. 반면 `new`와 `delete` 연산자(C는 `malloc()`과 `free()` 함수를 쓴다), 함수 중복, 참조와 참조에 의한 호출은 C에 없던 기능을 C++이 새로 추가한 것이다([1장 2.2절](Concepts_Lecture.ko.md#22-특징)).

> **참고:** C++은 `static_cast`, `dynamic_cast`, `const_cast`, `reinterpret_cast`처럼 변환의 의도를 드러내는 캐스트 연산자를 새로 도입했다. 이는 이미 있던 타입 변환을 더 안전하고 명확하게 쓰는 수단을 더한 것이며, 타입 변환이라는 기능 자체는 C에도 있었다.

### 이론 문제 16

**문제:** C++ 소스 파일, 목적 파일, 디버깅에 관한 네 설명 중 틀린 것을 고르라.

**정답:** ①

C++ 소스 파일은 사람이 읽고 쓸 수 있는 문자로 이루어진 텍스트 파일이므로 텍스트 편집기로 작성하고 수정할 수 있다([1장 4.1절](Concepts_Lecture.ko.md#41-빌드-파이프라인)). 바이너리 파일은 컴파일과 링킹의 결과로 만들어지는 목적 파일과 실행 파일이다.

나머지 설명은 옳다.

- ② 보통 `.cpp`를 쓰지만 컴파일러에 따라 `.cc`, `.cxx`, `.c++` 같은 확장자도 C++ 소스로 인식한다. 이 확장자들은 C++ 표준 문서가 정한 것이 아니라 컴파일러와 개발 도구의 관례이다.
- ③ 목적 파일의 확장자는 Windows(Visual Studio)에서 `.obj`, Linux와 macOS에서 `.o`이다.
- ④ 실행 중에 원하는 결과가 나오지 않거나 프로그램이 비정상 종료하는 오류를 찾아 고치는 과정이 디버깅이며, 이를 돕는 프로그램이 디버거이다([1장 4.3절](Concepts_Lecture.ko.md#43-실행과-디버깅)).

### 이론 문제 18

**문제:** `hello.obj`와 표준 C++ 라이브러리로 `hello.exe`를 만드는 그림에서 링킹의 의미를 설명하라.

**정답:** 링킹은 컴파일된 목적 파일(`hello.obj`)과 필요한 라이브러리의 코드를 하나로 묶어 실행 가능한 파일(`hello.exe`)을 만드는 과정이다. 이 과정에서 링커는 모듈 사이의 참조를 해결하고 주소를 확정하며, 필요한 라이브러리 함수(이 그림에서는 표준 C++ 라이브러리의 `cout` 객체와 `<<` 연산자 함수)를 연결한다.

`hello.cpp`를 컴파일하면 `hello.cpp`에 작성한 코드만 기계어로 번역된다. `cout`과 `<<` 연산자 함수는 `<iostream>`에 선언만 되어 있고 실제 코드는 표준 C++ 라이브러리에 들어 있으므로, `hello.obj`에는 이 이름들을 참조한다는 기록만 있고 그 내용은 비어 있다. 그림에서 `hello.obj`의 빈 퍼즐 자리가 이것이며, 이 때문에 목적 파일은 바로 실행할 수 없다.

링커는 목적 파일이 참조하지만 정의하지 않은 이름(미해결 심볼)을 라이브러리에서 찾아 연결하고, 여러 목적 파일과 라이브러리의 코드와 데이터를 하나의 실행 파일에 배치하면서 각 이름이 가리킬 주소를 확정한다. 빈 자리가 모두 채워져야 `hello.exe`가 완성되며, 정의를 찾지 못한 이름이 남으면 링크 오류가 발생한다([1장 4.2절](Concepts_Lecture.ko.md#42-오류의-종류)).

다음 `hello.cpp`를 macOS에서 컴파일만 하고 `nm`으로 목적 파일의 심볼을 보면, `std::cout`이 이 파일 안에 정의되지 않은 심볼(`U`)로 표시된다. libc++에서는 `std::cout`의 실제 이름이 `std::__1::cout`이다.

```cpp
#include <iostream>
int main() {
    std::cout << "Hello\n";
    return 0;
}
```

```text
$ g++ -std=c++17 -c hello.cpp -o hello.o
$ nm hello.o | c++filt | grep cout
                 U std::__1::cout
```

> **참고:** 라이브러리의 코드를 실행 파일 안에 복사해 넣는 방식을 정적 링킹(static linking)이라 하며, 그림은 이 방식을 나타낸다. 실행 파일에는 필요한 라이브러리와 이름만 기록하고, 프로그램을 실행할 때 운영체제가 라이브러리를 연결하는 방식은 동적 링킹(dynamic linking)이다. macOS의 Apple clang은 표준 C++ 라이브러리를 기본적으로 동적 라이브러리 `libc++.1.dylib`로 연결한다.

### 이론 문제 20

**문제:** C++ 표준 라이브러리에 포함되지 않는 것을 고르라.

**정답:** ①

C++ 표준 라이브러리는 기능에 따라 다음 세 그룹으로 구성된다([1장 3.1절](Concepts_Lecture.ko.md#31-표준-라이브러리의-구성)).

- **C 라이브러리:** 기존 C 표준 라이브러리의 함수를 수용한 것으로, `<cstring>`, `<cmath>`처럼 이름이 `c`로 시작하는 헤더에 선언된다.
- **C++ 입출력 라이브러리:** `<iostream>`, `<fstream>` 등이 제공하는 콘솔과 파일 입출력 기능이다.
- **C++ STL 라이브러리:** `vector`, `sort()`처럼 제네릭 프로그래밍을 지원하는 컨테이너, 알고리즘, 반복자의 템플릿 라이브러리이다.

네트워크 통신을 위한 라이브러리는 C++23까지의 표준 라이브러리에 포함되어 있지 않다. 네트워크 프로그램은 운영체제가 제공하는 소켓 API나 별도의 라이브러리를 사용하여 작성한다.

### 이론 문제 22

**문제:** C++ 통합 개발 환경이 무엇인지 설명하라.

**정답:** C++ 통합 개발 환경(IDE, integrated development environment)은 C++ 프로그램을 개발하는 데 필요한 여러 도구를 하나의 프로그램 안에서 제공하는 소프트웨어이다. C++ 소스 편집기, 컴파일러, 링커, 소스 레벨 디버거 등을 모두 갖추고 편집, 컴파일, 링킹, 실행, 디버깅의 모든 단계를 통합하여 지원한다.

IDE 없이 개발하면 텍스트 편집기로 소스를 작성한 뒤 명령 줄에서 컴파일러와 링커를 실행하고, 디버거도 따로 실행해야 한다. IDE는 이 도구들을 한 화면에서 연결하므로 빌드 명령 하나로 컴파일과 링킹을 수행하고, 컴파일 오류가 난 줄로 바로 이동하며, 소스 코드에 중단점을 두고 한 줄씩 실행하면서 변수 값의 변화를 볼 수 있다([1장 4.3절](Concepts_Lecture.ko.md#43-실행과-디버깅)). Windows의 Visual Studio와 macOS의 Xcode가 대표적인 C++ 통합 개발 환경이다.
