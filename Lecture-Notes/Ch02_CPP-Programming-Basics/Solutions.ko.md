### 이론 문제 2

**문제:** `main()` 함수의 리턴 타입과 `return` 문에 관한 네 설명 중 틀린 것을 고르라.

**정답:** ③

C++ 표준은 `main()` 함수에 한하여 `return` 문을 생략할 수 있게 한다. 실행이 `main()`의 끝에 도달하면 `return 0;`을 실행한 것과 같으므로 프로그램은 종료 코드 0을 운영체제에 돌려준다([2장 1.3절](Concepts_Lecture.ko.md#13-main-함수)). 이 예외는 `main()`에만 적용되며, 리턴 타입이 있는 다른 함수가 `return` 문 없이 끝에 도달하면 정의되지 않은 동작이 된다.

다음 프로그램에는 `return` 문이 없지만 `g++ -std=c++17 -Wall`로 경고 없이 컴파일되며, 실행한 뒤의 종료 코드는 0이다.

```cpp
#include <iostream>
int main() {
    std::cout << "no return statement\n";
}
```

나머지 설명을 보면 다음과 같다.

- ① C++ 표준은 `main()`의 리턴 타입을 `int`로 정한다.
- ② `void main()`은 표준이 아니며, Visual C++처럼 확장 기능으로 허용하는 컴파일러에서만 처리된다. Clang은 "'main' must return 'int'" 오류를 내므로 컴파일러에 따라서는 성립하지 않는 설명이다. 이식성을 위해 항상 `int main()`으로 쓴다.
- ④ `main()`의 리턴 값은 운영체제에 전달되는 종료 코드이며, 0은 정상 종료를 뜻한다. 오류를 알리려면 0이 아닌 값을 리턴할 수 있으므로 반드시 0을 리턴할 필요는 없다.

### 이론 문제 4

**문제:** 실행문 `a = 4;` 다음에 변수 `square`를 선언하는 코드가 C에서는 오류이고 C++에서는 정상인 이유와 그 특징의 장단점을 설명하라.

**정답:**

- (1) C89(C90) 표준의 C에서는 변수 선언이 블록의 시작 부분, 즉 실행문보다 앞에만 올 수 있으므로, 실행문 `a = 4;` 다음에 있는 3번째 줄 `int square = a * a;`에서 컴파일 오류가 발생한다.
- (2) C++에서는 변수 선언도 하나의 문장이므로 블록 안의 실행문 사이 어디에서나 변수를 선언할 수 있다.
- (3) 장점은 변수를 사용하는 시점에 선언할 수 있어 코드 작성이 편리하고, 선언부와 실행문 사이를 오가는 번거로움과 변수 이름의 타이핑 오류가 줄어드는 것이다. 단점은 변수 선언이 코드 곳곳에 흩어져 선언된 변수를 한눈에 보기 어렵고, 필요한 변수를 찾기 어려운 것이다.

(1)의 오류는 C89의 규칙에서 나온다. C99부터는 C도 실행문 사이의 변수 선언을 허용하므로 현재의 C 컴파일러는 기본 설정에서 이 코드를 컴파일한다. 다음 C 프로그램을 Clang에서 C89 규칙을 엄격하게 적용하는 옵션으로 컴파일하면 오류가 발생하고, `-std=c99`로 컴파일하면 정상적으로 컴파일되어 16을 출력한다.

```c
#include <stdio.h>

int main(void) {
    int a;
    a = 4;
    int square = a * a;
    printf("%d\n", square);
    return 0;
}
```

```text
$ clang -std=c89 -pedantic-errors square.c
square.c:6:9: error: mixing declarations and code is a C99 extension [-Werror,-Wdeclaration-after-statement]
```

변수의 유효 범위는 선언된 지점부터 그 블록의 끝까지이다. 따라서 변수를 사용하기 직전에 선언하면, 다른 변수 이름을 잘못 입력했을 때 그 이름이 아직 선언되지 않았으므로 컴파일 오류로 실수를 미리 발견할 수 있다. 반대로 모든 변수를 블록 앞에서 선언하면 잘못 입력한 이름도 이미 선언된 변수이므로 오류 없이 잘못된 결과만 나온다([2장 3.4절](Concepts_Lecture.ko.md#34-실행문-중간의-변수-선언)).

### 이론 문제 6

**문제:** `cout`을 `std::` 없이 쓰는 두 프로그램이 컴파일되도록 `#include <iostream>` 다음 빈칸에 들어갈 문장을 쓰라.

**정답:** (1) `using std::cout;` (2) `using namespace std;`

`cout`, `cin`, `endl`은 모두 `std` 네임스페이스에 선언된 이름이므로, `std::` 없이 쓰려면 using 선언이나 using 지시문이 필요하다([2장 4.2절](Concepts_Lecture.ko.md#42-using-namespace-std)). 빈칸을 비워 두면 Clang은 (1)의 `cout`에 대해 "use of undeclared identifier 'cout'" 오류를 낸다.

- (1) 이 프로그램은 `cin`을 `std::cin`으로 쓰고 `cout`만 `std::` 없이 쓰므로, `cout` 하나만 가져오는 using 선언 `using std::cout;`이 알맞다. `using namespace std;`를 써도 컴파일된다.
- (2) `cout`과 `endl`을 모두 `std::` 없이 쓰므로 `std`의 모든 이름을 쓸 수 있게 하는 using 지시문 `using namespace std;`를 쓴다. 한 줄에 `using std::cout; using std::endl;`처럼 두 using 선언을 써도 된다.

빈칸을 채운 두 프로그램 가운데 (1)은 입력한 정수에 1을 더해 출력한다(4를 입력하면 5).

### 이론 문제 8

**문제:** 네 줄의 C++ 코드에서 틀린 부분을 찾아 수정하라.

**정답:** (1)과 (2)는 틀린 곳이 없다. (3)은 `int n=1; cout << n+200;`, (4)는 `int year = 2014; cout << 2014 << "년";`으로 수정한다.

- (1) `std` 네임스페이스의 `cin` 하나만 가져오는 올바른 using 선언이다.
- (2) `int` 변수를 선언하고 1로 초기화한 문장이며, `//`부터 줄 끝까지는 주석이므로 오류가 없다.
- (3) `cout`은 출력 스트림이므로 스트림 삽입 연산자 `<<`를 써야 한다. `>>`는 `cin` 같은 입력 스트림에 쓰는 추출 연산자이며, `ostream`과 `int` 사이에는 `>>` 연산이 정의되어 있지 않으므로 "invalid operands to binary expression" 컴파일 오류가 발생한다. 수정한 코드는 `n+200`의 값 201을 출력한다.
- (4) `2014+"년"`은 문자열을 잇는 연산이 아니다. 문자열 리터럴 `"년"`은 첫 문자의 주소로 변환되므로 이 식은 그 주소에서 2014바이트 뒤를 가리키는 포인터 연산이 되며, 배열의 범위를 벗어나므로 정의되지 않은 동작이다. 컴파일은 되지만 Clang은 "adding 'int' to a string does not append to the string" 경고를 낸다. 정수와 문자열을 이어서 출력하려면 `<<`로 나누어 `cout << 2014 << "년";`으로 쓰며, 이 코드는 `2014년`을 출력한다. 선언한 변수를 쓰려면 `cout << year << "년";`으로 써도 된다.

### 이론 문제 10

**문제:** C 스트링과 `string` 클래스에 관한 다섯 문장에 O, X로 답하라.

**정답:** (1) O, (2) O, (3) O, (4) X, (5) X

- (1) O. C 스트링은 C 언어처럼 널 문자 `'\0'`으로 끝나는 `char` 배열로 문자열을 표현하는 방식이다([2장 5.1절](Concepts_Lecture.ko.md#51-c-스트링)).
- (2) O. C++은 C와의 호환성을 위해 C 스트링을 그대로 지원하며, `"C++"` 같은 문자열 리터럴도 C 스트링이다.
- (3) O. C++ 표준 라이브러리의 `string` 클래스(`<string>` 헤더)로 문자열을 객체로 다룬다([2장 5.2절](Concepts_Lecture.ko.md#52-string-클래스)).
- (4) X. 문자열 리터럴 `"C++"`의 끝에는 널 문자 `'\0'`이 붙으므로 `name[]`은 `'C'`, `'+'`, `'+'`, `'\0'`을 저장하는 크기 4의 배열이 된다. `sizeof(name)`을 출력하면 4이다.
- (5) X. `>>`는 공백 문자를 만나면 입력을 끝내므로 공백 문자를 포함하여 읽을 수 없다. 공백을 포함한 문자열은 `cin.getline()`으로 읽는다.

> **참고:** (5)의 최대 문자 수는 C++ 표준의 버전에 따라 다르다. C++17까지의 `>>`는 배열의 크기를 알지 못하므로, `char name[10]`에 공백 없는 15글자를 입력하면 15글자를 모두 저장하여 배열 밖의 메모리를 덮어쓴다. C++20부터는 배열을 참조로 받아 크기를 알 수 있으므로 9글자까지만 저장하고 나머지는 입력 버퍼에 남긴다. Apple clang에서 `-std=c++17`과 `-std=c++20`으로 각각 컴파일하여 `ABCDEFGHIJKLMNO`를 입력하면 저장되는 문자열의 길이가 15와 9로 다르다.

### 이론 문제 12

**문제:** 이름을 `cin >> name`으로 읽어 환영 메시지를 출력하는 프로그램에 Kitae와 Kitae Hwang을 각각 입력한 결과를 쓰라.

**정답:** (1)과 (2) 모두 `Kitae님 환영합니다`가 출력된다.

(1) 입력한 `Kitae`가 `name`에 저장되므로 `Kitae님 환영합니다`가 출력된다. 프로그램은 줄바꿈을 출력하지 않지만, 사용자가 누른 `<Enter>`가 화면에 반영되어 출력은 다음 줄에 나타난다.

```text
이름을 입력하세요?Kitae
Kitae님 환영합니다
```

(2) `>>` 연산자는 앞의 공백을 건너뛴 뒤 다음 공백 문자 직전까지만 읽으므로 `name`에는 `Kitae`만 저장되고, 그 뒤의 공백 문자와 `Hwang`은 `<Enter>`의 줄바꿈 문자와 함께 입력 버퍼에 남는다. 따라서 출력은 (1)과 같다.

```text
이름을 입력하세요?Kitae Hwang
Kitae님 환영합니다
```

이 프로그램은 버퍼에 남은 `Hwang`을 더 읽지 않고 종료한다. 공백을 포함한 이름 전체를 읽으려면 `std::cin >> name;` 대신 `std::cin.getline(name, 20);`을 쓴다.

### 이론 문제 14

**문제:** `I love C++<Enter>`를 `char buf[100]`에 읽는 네 코드 중 잘못된 것을 고르라.

**정답:** ①

`cin >> buf;`는 공백 문자를 만나면 입력을 끝내므로 `buf`에는 `I`만 저장되고, `<Enter>`까지 입력된 한 줄 전체를 읽을 수 없다.

`cin.getline(buf, size, delimitChar)`는 최대 `size - 1`개의 문자를 읽고, `delimitChar`를 만나면 그 문자를 입력 버퍼에서 꺼내 버린 뒤 입력을 멈추며, 끝에 `'\0'`을 붙인다. 세 번째 인자의 기본값은 `'\n'`이다([2장 5.1절](Concepts_Lecture.ko.md#51-c-스트링)).

- ② `cin.getline(buf, 11);`은 구분 문자가 `'\n'`이고 최대 10개의 문자를 읽는다. `I love C++`는 공백을 포함하여 정확히 10개의 문자이므로 모두 저장되고, 뒤의 `'\n'`도 꺼내 버린다.
- ③ `cin.getline(buf, 20, '\n');`은 최대 19개의 문자를 읽으며 `<Enter>`를 만나 멈추므로 `I love C++` 전체가 저장된다.
- ④ `cin.getline(buf, 11, '.');`도 10개의 문자를 읽은 시점에서 멈추므로 `buf`에는 `I love C++`가 저장된다.

> **참고:** ④는 `<Enter>`가 아니라 최대 문자 수 때문에 멈춘다. `getline()`은 구분 문자를 만나기 전에 `size - 1`개의 문자를 저장하면 스트림에 실패 상태(failbit)를 설정하므로, ④를 실행하면 `cin.fail()`이 참이 되고 `'\n'`은 입력 버퍼에 남는다. 이후의 입력은 `cin.clear()`로 상태를 지우기 전까지 모두 실패한다. 반면 ②는 10개의 문자를 저장한 직후 다음 문자가 구분 문자 `'\n'`이므로 실패 상태가 되지 않는다. 입력이 10개의 문자보다 길면 ②와 ④ 모두 앞의 10개만 저장하므로, 이 문제에서 ②와 ④가 한 줄 전체를 읽는 것은 입력이 정확히 10개의 문자이기 때문이다.

### 이론 문제 16

**문제:** C++ 표준 라이브러리의 모든 이름이 선언된 네임스페이스를 쓰라.

**정답:** `std`

C++ 표준 라이브러리는 `cout`, `cin`, `endl`, `string`, `vector` 같은 이름을 모두 `std` 네임스페이스 안에 선언한다. 따라서 표준 라이브러리의 이름은 `std::cout`처럼 네임스페이스를 붙여 쓰거나, `using std::cout;` 또는 `using namespace std;`를 선언한 뒤 이름만 쓴다([2장 4.1절](Concepts_Lecture.ko.md#41-개념)). 네임스페이스는 여러 사람이 나누어 개발하거나 다른 사람의 라이브러리를 가져다 쓸 때 같은 이름이 충돌하는 것을 막는다.

### 이론 문제 18

**문제:** C++ 표준에서 `cin`과 `cout` 객체가 선언된 헤더 파일을 쓰라.

**정답:** `<iostream>`

`<iostream>` 헤더 파일에는 표준 입출력을 위한 클래스(`ios`, `istream`, `ostream`, `iostream`)와 객체 `cin`, `cout`, 그리고 `<<`와 `>>` 연산자 함수가 선언되어 있다([2장 1.4절](Concepts_Lecture.ko.md#14-include-iostream)). `cin`은 키보드에 연결된 `istream` 타입의 객체이고, `cout`은 화면에 연결된 `ostream` 타입의 객체이다. 헤더 파일에는 선언만 있고 실제 객체는 표준 C++ 라이브러리에 들어 있어 링크할 때 연결된다([2장 7.4절](Concepts_Lecture.ko.md#74-헤더-파일과-라이브러리)). 표준 C++에서는 `.h`가 붙은 `<iostream.h>`를 쓰지 않는다.

### 이론 문제 20

**문제:** 바깥 `for` 문 안의 빈칸 세 줄을 채워 `*`를 한 줄에 하나부터 네 개까지 늘려 가며 출력하는 프로그램을 완성하라.

**정답:**

```cpp
for(int i=0; i<=n; i++) {
   cout << "*";
}
cout << endl;
```

빈칸을 채운 프로그램과 실행 결과는 다음과 같다.

```cpp
#include <iostream>
using namespace std;
int main() {
   for(int n=0; n<4; n++) {
      for(int i=0; i<=n; i++) {
         cout << "*";
      }
      cout << endl;
   }
}
```

**실행 결과:**

```text
*
**
***
****
```

바깥 `for` 문의 `n`은 0부터 3까지 변하며 출력할 줄을 정한다. 안쪽 `for` 문은 `i`가 0부터 `n`까지 `n + 1`번 반복하므로 `n`이 0, 1, 2, 3일 때 `*`를 각각 1, 2, 3, 4개 출력하고, 안쪽 반복이 끝나면 `endl`로 줄을 바꾼다. 본문이 한 문장인 `for` 문은 중괄호를 생략할 수 있으므로 빈칸 세 줄에 맞추어 `for(int i=0; i<=n; i++)`, `cout << "*";`, `cout << endl;`의 세 줄로 써도 같은 결과가 나온다.
