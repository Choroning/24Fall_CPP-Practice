## 2. Q1. 정수와 객체를 더하는 프렌드 연산자 함수

### 2.1 요구사항

`Circle` 클래스에 연산자를 추가하여 `b = 1 + a;`가 `b`의 반지름을 `a`의 반지름에 1을 더한 값으로 바꾸게 한다. 왼쪽 피연산자가 `int`이고 오른쪽 피연산자가 `Circle`인 이항 연산이므로, 연산자 함수를 구현하는 두 방식 중 하나만 쓸 수 있다.

| 구현 방식 | `1 + a`의 변환 | 가능 여부 |
|:-----|:-----|:-----|
| 멤버 함수 | `1.operator+(a)` | 불가능하다. `int`는 클래스가 아니므로 멤버 함수를 추가할 수 없다 |
| 외부 함수 | `operator+(1, a)` | 가능하다. `radius`가 `private`이므로 `Circle`의 프렌드로 선언한다 |

*표 1. `1 + a`를 구현하는 두 방식의 비교*

### 2.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Circle` 클래스는 원을 표현하며, 반지름 `radius`를 `private` 멤버 변수로 둔다. `public` 아래에는 생성자와 `show()`를 두고, `friend` 키워드로 클래스 밖의 `+` 연산자 함수가 `private` 멤버에 접근할 수 있게 하였다.

- **생성자:** 반지름 `radius`를 받으며 디폴트 값은 0이다. `this->radius = radius;`로 매개변수의 값을 멤버 변수에 대입한다.
- **`show()`:** `radius = 5 인 원`처럼 반지름을 출력한다.
- **프렌드 선언:** `friend Circle operator+ (int op1, Circle op2);`는 이 이름의 외부 함수가 `Circle`의 `private` 멤버에 접근할 수 있게 한다. 프렌드 선언은 함수를 클래스의 멤버로 만들지 않는다.
- **`operator+(int op1, Circle op2)`:** 클래스 밖에서 `Circle::` 없이 정의한다. 기본 생성자로 임시 객체 `tmp`를 만들고, `tmp.radius`에 `op1 + op2.radius`를 저장하여 `tmp`를 값으로 리턴한다. 프렌드이므로 `tmp.radius`와 `op2.radius`에 직접 접근할 수 있다([7장 1.1절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#11-프렌드-함수), [7장 3.2절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#32-프렌드-함수로-구현)).

`main()`은 반지름이 5인 `a`와 4인 `b`를 만들고, `b = 1 + a;`로 `operator+(1, a)`가 리턴한 반지름 6의 객체를 `b`에 대입한다. `a`는 값 매개변수 `op2`로 복사되어 전달되므로 바뀌지 않는다.

다음 네 가지는 이 설계의 성질이다.

- **피연산자의 순서:** 이 함수는 `int`가 왼쪽, `Circle`이 오른쪽인 경우만 처리한다. `a + 1`은 첫 번째 매개변수 `int`에 `Circle`을 넘길 수 없으므로 `invalid operands to binary expression ('Circle' and 'int')` 오류가 난다. `a + 1`도 지원하려면 `Circle operator+(int op)` 멤버 함수나 `friend Circle operator+(Circle op1, int op2)`를 따로 둔다.
- **프렌드 선언의 역할:** 클래스 안의 `friend` 선언을 지우면 외부 함수 `operator+`가 `private` 멤버에 접근하게 되어 `'radius' is a private member of 'Circle'` 오류가 난다. `Circle`에 `public` get/set 함수가 있다면 프렌드 없이 일반 외부 함수로도 구현할 수 있다.
- **매개변수 전달 방식:** `op2`는 값으로 전달되므로 호출할 때마다 `a`가 복사된다. 피연산자를 바꾸지 않는 이항 연산자는 보통 `const Circle&`로 받는다.
- **연쇄된 덧셈:** `1 + 2 + a`는 `(1 + 2) + a`로 정수 덧셈을 먼저 하여 `operator+(3, a)`가 되므로 반지름 8의 원이 된다. 반면 `1 + a + 2`는 `(1 + a) + 2`, 즉 `Circle + int`가 되어 이 코드에서는 컴파일되지 않는다.

### 2.3 실행 결과와 검토

```text
radius = 5 인 원
radius = 6 인 원
```

첫 줄은 바뀌지 않은 `a`이고, 둘째 줄은 `1 + a`의 결과를 대입받은 `b`이다. `b`가 처음 가졌던 반지름 4는 대입으로 사라진다.

## 3. Q2. 프렌드 함수로 중복한 전위와 후위 증가 연산자

### 3.1 요구사항

`Circle` 클래스의 전위 `++`와 후위 `++`를 프렌드 함수로 작성한다. `++a;`는 `a`의 반지름을 1 늘리고, `b = a++;`는 증가하기 전의 `a`를 `b`에 대입한 뒤 `a`의 반지름을 1 늘린다.

| 문장 | 프렌드 함수의 호출 | 리턴값 | 실행 후의 `a`, `b` |
|:-----|:-----|:-----|:-----|
| `++a;` | `operator++(a)` | 반지름 6인 복사본 (쓰이지 않음) | `a`는 6, `b`는 4 |
| `b = a++;` | `operator++(a, 0)` | 반지름 6인 복사본 (`b`에 대입) | `a`는 7, `b`는 6 |

*표 2. Q2의 전위와 후위 `++`의 호출*

### 3.2 설계와 해결 방법

`Circle` 클래스의 멤버 변수, 생성자, `show()`는 Q1과 같다. 클래스 안에는 두 `operator++`의 프렌드 선언을 두고, 몸체는 클래스 밖에서 정의하였다.

- **전위 `operator++(Circle& op)`:** 참조로 받은 객체의 `radius`를 1 늘리고 그 객체를 리턴한다. 리턴 타입이 `Circle`이므로 증가한 뒤의 객체의 복사본이 리턴된다.
- **후위 `operator++(Circle& op, int notUsed)`:** `Circle tmp = op;`로 증가하기 전의 상태를 복사해 두고, 원래 객체의 `radius`를 1 늘린 뒤 `tmp`를 리턴한다. 두 번째 매개변수 `int`는 값이 쓰이지 않으며 전위와 후위를 구분하기 위해서만 있다. 컴파일러는 `a++`를 `operator++(a, 0)`처럼 의미 없는 정수를 넘겨 호출한다([7장 4.3절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#43-증가--감소-연산자)).

두 함수는 모두 피연산자를 `Circle&`로 받는다. 프렌드 함수에는 `this`가 없으므로 바꿀 객체를 매개변수로 받아야 하며, 값으로 받으면 함수 안의 복사본만 바뀐다. 실제로 두 매개변수를 `Circle op`로 바꾸면 `a`는 끝까지 반지름 5로 남아 `radius = 5 인 원`이 두 번 출력된다.

`main()`은 반지름이 5인 `a`와 4인 `b`를 만든 뒤 `++a;`로 `a`를 6으로 만든다. `b = a++;`에서는 후위 함수가 증가하기 전의 복사본(반지름 6)을 리턴하여 `b`에 대입되고, 그사이 `a`는 7이 된다.

후위 함수가 `Circle`을 값으로 리턴하는 것은 올바르다. 증가하기 전의 상태는 지역 객체 `tmp`에만 남아 있으므로, 참조를 리턴하면 함수가 끝난 뒤 사라진 객체를 가리키게 된다. 반면 전위 `++`는 증가한 객체 자신을 결과로 내므로 보통 `Circle& operator++(Circle& op)`처럼 참조를 리턴한다([7장 4.4절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#44-전위-vs-후위-상세-추적)). 이 풀이처럼 전위에서 복사본을 리턴하면 결과가 임시 객체가 되어 다음과 같은 차이가 생긴다.

- **`++(++a)`:** 안쪽 `++a`가 임시 복사본을 리턴하는데, 바깥쪽 `operator++`는 `Circle&`를 받으므로 임시 객체를 넘길 수 없다. 그래서 `cannot increment value of type 'Circle'` 오류로 컴파일되지 않는다. 리턴 타입을 `Circle&`로 바꾸면 컴파일되고 `a`가 두 번 증가하여 반지름 7이 된다.
- **멤버 함수와의 차이:** 같은 전위 `++`를 복사본을 리턴하는 멤버 함수 `Circle operator++()`로 만들면, 멤버 함수는 임시 객체에 대해서도 호출할 수 있으므로 `++(++a)`가 컴파일된다. 그러나 두 번째 증가는 임시 객체에 적용되어 `a`는 한 번만 증가한 반지름 6이 된다.
- **복사 비용:** 결과를 쓰지 않는 `++a;`에서도 리턴할 때마다 객체가 한 번 복사된다.

`notUsed`는 값이 쓰이지 않는 매개변수이므로 `-Wextra`를 더해 컴파일하면 `unused parameter 'notUsed'` 경고가 나온다. `-Wall`에는 이 경고가 포함되지 않는다. 정의에서 매개변수 이름을 생략하여 `Circle operator++(Circle& op, int)`로 쓰면 경고가 사라진다.

### 3.3 실행 결과와 검토

```text
radius = 7 인 원
radius = 6 인 원
```

`main()`의 두 주석은 모두 반지름을 1 증가시킨다고 적었고, 실제로 두 문장은 모두 `a`의 반지름을 1씩 늘려 `a`는 5에서 7이 된다. 두 문장의 차이는 리턴값에 있으며, `b`는 두 번째 증가가 일어나기 전의 값 6을 받는다.

## 4. Q3. 배열과 원소를 주고받는 Matrix 클래스의 연산자

### 4.1 요구사항

2×2 행렬의 네 원소를 배열 `ar`에 저장하는 `Matrix` 클래스에서, `a >> x`는 `a`의 원소를 배열 `x`에 복사하고 `b << y`는 배열 `y`의 원소로 `b`의 원소를 설정하게 한다. (1)은 두 연산자 함수를 `Matrix`의 멤버 함수로, (2)는 프렌드 함수로 구현하는 문제이다.

| 식 | 멤버 함수일 때의 호출 | 프렌드 함수일 때의 호출 |
|:-----|:-----|:-----|
| `a >> x` | `a.operator>>(x)` | `operator>>(a, x)` |
| `b << y` | `b.operator<<(y)` | `operator<<(b, y)` |

*표 3. Q3의 연산자 식과 두 구현 방식의 호출 형태*

### 4.2 설계와 해결 방법

`Matrix` 클래스의 멤버 변수 `ar[4]`, 두 생성자, `show()`는 문제에 주어진 코드와 같다. 기본 생성자는 네 원소를 0으로, 인자 4개 생성자는 `ar[0]`부터 `ar[3]`까지를 차례로 초기화하고, `show()`는 `Matrix = { 1 2 3 4 }` 형식으로 원소를 출력한다. 여기의 `<<`와 `>>`는 왼쪽 피연산자가 `Matrix`이므로 멤버 함수로 구현할 수 있으며, 왼쪽 피연산자가 `ostream`인 스트림 출력의 `<<`와는 경우가 다르다([7장 5절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#5-스트림-연산자-중복)).

(1)의 멤버 함수 버전에서는 왼쪽 피연산자인 `Matrix` 객체가 `this`이므로 매개변수가 오른쪽 피연산자인 배열 하나뿐이다.

- **`int* operator >> (int op[])`:** `ar`의 네 원소를 `op`에 복사하고 `op`를 리턴한다. 매개변수 `int op[]`는 실제로는 포인터 `int*`이므로 `main()`의 배열 `x` 자체에 값이 저장된다.
- **`Matrix& operator << (int op[])`:** `op`의 네 원소를 `ar`에 복사하고 `*this`의 참조를 리턴한다.

(2)의 프렌드 함수 버전은 클래스 안의 블록 주석(41~52행)에 있다. 프렌드 함수에는 `this`가 없으므로 왼쪽 피연산자인 `Matrix`를 첫 번째 매개변수 `op1`로, 배열을 두 번째 매개변수 `op2`로 받는다. 클래스 안에서 몸체까지 정의하였지만 `friend`가 붙은 함수는 멤버 함수가 아니며, `op1.ar`처럼 매개변수를 통해 `private` 멤버에 접근한다([7장 2.4절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#24-멤버-함수-vs-프렌드-함수-판단-가이드)).

- **`friend int* operator>>(Matrix& op1, int op2[])`:** `op1.ar`의 원소를 `op2`에 복사하고 `op2`를 리턴한다.
- **`friend Matrix& operator<<(Matrix& op1, int op2[])`:** `op2`의 원소를 `op1.ar`에 복사하고 `op1`의 참조를 리턴한다. `op1`을 참조로 받으므로 `b` 자체가 바뀌며, 값으로 받으면 복사본만 바뀐다.

두 버전은 매개변수 목록만 다르고 하는 일과 리턴값은 같다. 리턴 타입은 연산의 결과를 이어서 쓸 수 있게 정하였다. `<<`는 객체의 참조를 리턴하므로 `b << y << x;`처럼 연쇄할 수 있으며, 이 문장은 `b`를 `y`의 값으로 설정한 뒤 다시 `x`의 값으로 설정하여 `Matrix = { 4 3 2 1 }`을 만든다. `>>`는 값을 받은 배열의 주소를 리턴하므로 `(a >> x)[0]`처럼 결과를 바로 배열로 쓸 수 있다. 다만 `a >> x >> y`는 `(a >> x)`가 `int*`이고 `int*`와 배열 사이의 `>>`는 정의되어 있지 않으므로 컴파일되지 않는다.

`main()`은 `a`를 (4, 3, 2, 1)로, `b`를 모든 원소가 0인 행렬로 만들고, `a >> x;`로 `x`에 4, 3, 2, 1을 복사한 뒤 `b << y;`로 `b`의 원소를 1, 2, 3, 4로 설정한다. 이어서 `x`의 원소를 출력하고 `b.show()`로 `b`를 출력한다.

프렌드 함수 버전으로 바꾸려면 다음과 같이 한다.

1. 멤버 함수 버전(27~39행)을 지우거나 각 줄 앞에 `//`를 붙여 주석으로 만든다.
2. 41행의 `/*`를 `//`로 바꾸어 설명 문구만 한 줄 주석으로 남긴다. `/*`만 지우면 `(2) <<, >>를 ...`이 코드로 해석되어 컴파일 오류가 난다.
3. 52행 끝의 `*/`를 지운다.

이렇게 바꾼 코드는 멤버 함수 버전과 같은 결과를 출력한다. 멤버 함수 버전을 남겨 둔 채 프렌드 함수 버전의 주석만 풀면, `a >> x`에 대해 `a.operator>>(x)`와 `operator>>(a, x)`가 똑같이 일치하므로 `use of overloaded operator '>>' is ambiguous` 오류가 나고 `<<`도 마찬가지이다. 그래서 두 버전 중 하나만 활성화해야 한다.

코드를 더 견고하게 만들려면 배열의 크기를 고려할 수 있다. `int op[]`는 포인터이므로 함수는 넘겨받은 배열의 크기를 알 수 없고, 언제나 네 원소를 읽거나 쓴다. 원소가 4개보다 적은 배열을 넘기면 배열의 범위를 벗어난 메모리에 접근하게 되므로, 크기가 고정된 배열의 참조 `int (&op)[4]`로 받으면 크기가 다른 배열을 넘기는 코드를 컴파일 단계에서 막을 수 있다.

### 4.3 실행 결과와 검토

```text
4 3 2 1 
Matrix = { 1 2 3 4 }
```

첫 줄 끝의 공백은 `cout << x[i] << ' ';`이 원소마다 뒤에 공백을 붙이기 때문이다. 첫 줄은 `a`의 원소가 `x`에 복사된 결과이고, 둘째 줄은 `y`의 원소로 설정된 `b`이다. 프렌드 함수 버전으로 바꾸어도 두 줄이 똑같이 출력된다.

## 요약

| 개념 | 핵심 요약 |
|:-----|:-----|
| 프렌드 함수 | `friend`로 선언한 외부 함수는 클래스의 멤버가 아니지만 그 클래스의 `private` 멤버에 접근할 수 있다. |
| 왼쪽 피연산자가 기본 타입인 연산 | `int`에는 멤버 함수를 추가할 수 없으므로 `1 + a`는 `operator+(1, a)` 형태의 외부 함수로만 구현할 수 있다. |
| 전위와 후위의 구분 | 후위 연산자 함수는 쓰이지 않는 `int` 매개변수를 하나 더 가지며, 컴파일러는 `a++`를 `operator++(a, 0)`으로 호출한다. |
| 프렌드 단항 연산자의 매개변수 | 프렌드 함수에는 `this`가 없으므로 바꿀 객체를 `Circle&`처럼 참조로 받아야 원본이 바뀐다. |
| 전위의 리턴 타입 | 전위 `++`는 보통 참조를 리턴하며, 복사본을 리턴하면 `++(++a)`가 프렌드 버전에서는 컴파일되지 않고 멤버 버전에서는 한 번만 증가한다. |
| 멤버와 프렌드의 매개변수 목록 | 멤버 버전은 오른쪽 피연산자만, 프렌드 버전은 두 피연산자를 모두 매개변수로 받으며, 두 버전이 함께 있으면 호출이 모호해진다. |
| 연쇄를 위한 리턴 타입 | `Matrix&`를 리턴하는 `<<`는 `b << y << x`처럼 연쇄할 수 있고, `int*`를 리턴하는 `>>`는 결과를 바로 배열로 쓸 수 있다. |

## 점검 문제

1. **멤버 함수의 한계:** Q1의 `1 + a`를 `Circle`의 멤버 함수로 구현할 수 없는 이유는 무엇인가?

   <details>
   <summary>정답</summary>

   멤버 연산자 함수는 왼쪽 피연산자의 멤버로 호출되므로 `1 + a`는 `1.operator+(a)`가 되어야 한다. 그러나 `int`는 클래스가 아니어서 멤버 함수를 추가할 수 없다. 그래서 두 피연산자를 모두 매개변수로 받는 외부 함수 `operator+(int, Circle)`로 구현하고, `private` 멤버 `radius`에 접근하기 위해 `Circle`의 프렌드로 선언한다.

   </details>

2. **피연산자의 순서:** Q1의 `main()`에서 `b = 1 + a;`를 `b = a + 1;`로 바꾸면 어떻게 되며, 이 식을 지원하려면 무엇을 추가하는가?

   <details>
   <summary>정답</summary>

   `operator+(int, Circle)`의 첫 번째 매개변수에 `Circle`을 넘길 수 없으므로 컴파일 오류가 난다. `Circle operator+(int op)`를 멤버 함수로 추가하거나 `friend Circle operator+(Circle op1, int op2);`를 선언하고 정의하면 `a + 1`이 컴파일되고, `b`는 반지름 6의 원이 된다.

   </details>

3. **전위와 후위의 추적:** Q2의 `Circle` 클래스로 `Circle a(5), b(4), c(0); c = a++; b = ++a;`를 실행하면 `a`, `b`, `c`의 반지름은 각각 얼마인가?

   <details>
   <summary>정답</summary>

   `c = a++;`에서 `c`는 증가하기 전의 값 5를 받고 `a`는 6이 된다. `b = ++a;`에서 `a`는 7이 되고 `b`는 증가한 뒤의 값 7을 받는다. 따라서 `a`는 7, `b`는 7, `c`는 5이다.

   </details>

4. **값으로 받은 피연산자:** Q2의 두 `operator++`가 피연산자를 `Circle& op`가 아니라 `Circle op`로 받으면 출력은 어떻게 되는가?

   <details>
   <summary>정답</summary>

   두 함수가 `a`의 복사본만 증가시키므로 `a`의 반지름은 5로 남는다. 후위 함수는 복사본 `op`를 다시 복사한 `tmp`(반지름 5)를 리턴하므로 `b`도 5가 된다. 출력은 `radius = 5 인 원`이 두 번이다.

   </details>

5. **두 버전의 공존:** Q3에서 멤버 함수 버전을 그대로 둔 채 41행의 `/*`와 52행의 `*/`만 정리하여 프렌드 함수 버전을 활성화하면 어떻게 되는가?

   <details>
   <summary>정답</summary>

   `a >> x`에 대해 멤버 함수 `a.operator>>(x)`와 프렌드 함수 `operator>>(a, x)`가 똑같이 일치하므로 컴파일러가 하나를 고를 수 없어 `use of overloaded operator '>>' is ambiguous` 오류가 난다. `b << y`도 같은 오류가 난다. 두 버전 중 하나를 지우거나 주석으로 막아야 한다.

   </details>
