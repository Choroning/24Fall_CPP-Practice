## 2. Q1. 복합 대입 연산자를 갖춘 Book 클래스

### 2.1 요구사항

`Book` 클래스에 `+=`와 `-=` 연산자 함수를 멤버 함수로 추가하여, `a += 500;`은 책 `a`의 가격을 500원 올리고 `b -= 500;`은 책 `b`의 가격을 500원 내리게 한다. 문제는 `c = a += 500;`처럼 연산의 결과를 다른 객체에 대입하는 코드도 동작하도록 고려하라고 한다. 각 식은 다음과 같이 연산자 함수의 호출로 바뀐다.

| 식 | 연산자 함수의 호출 | 하는 일 |
|:-----|:-----|:-----|
| `a += 500` | `a.operator+=(500)` | `a`의 `price`에 500을 더한다 |
| `b -= 500` | `b.operator-=(500)` | `b`의 `price`에서 500을 뺀다 |
| `c = a += 500` | `c.operator=(a.operator+=(500))` | 대입 연산자는 오른쪽부터 결합하므로 `a`의 가격을 먼저 올리고 그 결과를 `c`에 대입한다 |

*표 2. Q1의 연산자 식과 연산자 함수의 호출*

### 2.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Book` 클래스는 책 한 권을 표현하며, 책의 제목 `title`, 가격 `price`, 쪽수 `pages`를 `private` 멤버 변수로 둔다. 세 멤버는 접근 지정자 없이 클래스의 맨 앞에 선언되었으므로 `class`의 기본 접근 지정에 따라 `private`이 된다. `public` 아래에는 생성자, `show()`, get/set 함수, 두 연산자 함수를 둔다.

- **생성자:** 매개변수 `title`, `price`, `pages`의 디폴트 값은 각각 `""`, 0, 0이다. 매개변수와 멤버 변수의 이름이 같으므로 `this->title = title;`처럼 `this` 포인터로 멤버 변수를 가리켜 대입한다.
- **`show()`:** 책의 제목, 가격, 쪽수를 한 줄에 출력한다.
- **`getTitle()`, `getPrice()`, `setPrice()`:** 제목과 가격을 리턴하는 get 함수와 가격을 바꾸는 set 함수이다. 이 `main()`에서는 쓰이지 않으며, [실습 2-1]의 일반 함수 `Sub()`처럼 클래스 밖에서 `private` 멤버인 `price`를 바꾸려면 이 함수들이 필요하다.
- **`operator+=(int op)`:** `this->price += op;`로 가격을 올리고 `return *this;`로 객체를 리턴한다.
- **`operator-=(int op)`:** `this->price -= op;`로 가격을 내리고 같은 방식으로 객체를 리턴한다.

두 연산자 함수는 멤버 함수이므로 왼쪽 피연산자인 객체가 `this`가 되고, 오른쪽 피연산자 500이 매개변수 `op`로 전달된다([7장 2.2절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#22-개념)). `main()`은 `a`와 `b`를 만들고 `a += 500;`, `b -= 500;`으로 가격을 바꾼 뒤 `show()`로 두 책의 정보를 출력한다. `a`의 가격은 20000에서 20500으로, `b`의 가격은 30000에서 29500으로 바뀐다.

`return *this;`만 보면 객체 자신을 리턴하는 것처럼 보이지만, 두 함수의 리턴 타입이 `Book`이므로 실제로는 `*this`를 복사한 새 객체가 리턴된다. 객체 자신의 참조를 리턴하려면 리턴 타입이 `Book&`이어야 한다. 이 차이는 연산의 결과를 다시 쓰는 식에서 드러난다.

- **`c = a += 500;`:** `a += 500`이 먼저 실행되어 `a`의 가격이 바뀌고, 리턴된 복사본이 `c`에 대입된다. 복사본은 바뀐 뒤의 `a`와 내용이 같으므로 이 식은 복사본을 리턴해도 의도대로 동작한다. 문제가 요구한 `c = a += 500;`은 현재 코드로도 컴파일되고 `c`의 가격이 `a`와 같은 20500이 된다.
- **`(a += 500) += 100;`:** 두 번째 `+=`는 첫 번째 `+=`가 리턴한 임시 복사본에 적용되므로 `a`의 가격은 500만 오른다. `a`가 20500원일 때 이 문장을 실행하면 `a`는 21100원이 아니라 21000원이 된다. 리턴 타입을 `Book&`로 바꾸면 두 번째 `+=`도 `a`에 적용되어 21100원이 된다.

그래서 복합 대입 연산자는 보통 `Book& operator+=(int op)`처럼 `*this`의 참조를 리턴한다. 참조를 리턴하면 연쇄된 연산이 모두 같은 객체에 적용되고, 리턴할 때마다 `string` 멤버를 포함한 객체 전체를 복사하는 비용도 없어진다([7장 3.3절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#33-복합-대입-연산자), [7장 8절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#8-흔한-실수)).

### 2.3 실행 결과와 검토

```text
청춘 20500원 300페이지
미래 29500원 500페이지
```

두 책의 가격은 문제의 실행 예시와 같이 20500원과 29500원이다. 풀이는 `string`을 쓰면서 `<string>`을 포함하지 않는데, macOS의 libc++에서는 `<iostream>`이 `<string>`을 간접적으로 포함하므로 컴파일된다. 표준은 이를 보장하지 않으므로 이식성 있는 코드는 `<string>`을 직접 포함한다. Q2와 Q3도 같다.

## 3. Q2. 두 가지 비교 연산자를 갖춘 Book 클래스

### 3.1 요구사항

`Book` 클래스에 두 가지 `==` 연산자 함수를 멤버 함수로 추가한다. `a == "명품 C++"`는 책의 제목을 문자열과 비교하고, `a == b`는 `main()`의 주석에 따르면 두 책의 제목, 가격, 쪽수를 모두 비교한다. 참조 질문은 `!=` 연산자 함수를 멤버 함수로 제공하는 방법을 묻는다.

| 식 | 연산자 함수의 호출 | 비교 대상 |
|:-----|:-----|:-----|
| `a == "명품 C++"` | `a.operator==(string("명품 C++"))` | `a`의 제목과 문자열 |
| `a == b` | `a.operator==(b)` | 두 책 (주석에 따르면 제목, 가격, 쪽수) |

*표 3. Q2의 두 `==` 식과 연산자 함수의 호출*

### 3.2 설계와 해결 방법

`Book` 클래스의 멤버 변수, 생성자, `show()`는 Q1과 같고, get 함수는 `getTitle()`만 둔다. `==` 연산자 함수는 매개변수의 타입이 다른 두 함수로 중복하였다.

- **`operator==(string op)`:** `this->title == op`이면 `true`, 아니면 `false`를 리턴한다.
- **`operator==(Book op)`:** `this->title == op.title`이면 `true`, 아니면 `false`를 리턴한다. `op`는 같은 클래스의 객체이므로 멤버 함수 안에서 `op.title`처럼 `private` 멤버에 직접 접근할 수 있다.

`main()`은 제목만 다르고 가격과 쪽수가 같은 `a`와 `b`를 만든다. `a == "명품 C++"`는 참이므로 `명품 C++ 입니다.`를 출력하고, `a == b`는 제목이 달라 거짓이므로 `두 책은 다른 책입니다.`를 출력한다.

`a == "명품 C++"`의 오른쪽 피연산자는 문자열 리터럴, 즉 `const char` 배열이다. 이 값은 `string`의 생성자를 거치는 사용자 정의 변환 한 번으로 `string`이 되므로 `operator==(string)`이 호출된다. `Book`이 되려면 `const char*`에서 `string`으로, `string`에서 `Book`으로 사용자 정의 변환이 두 번 필요한데, 암시적 변환에는 사용자 정의 변환이 한 번만 허용되므로 `operator==(Book)`은 후보가 되지 못한다([6장 1.2절](../../Lecture-Notes/Ch06_Overloading-and-Static-Members/Concepts_Lecture.ko.md#12-오버로딩-해석-규칙)). 실제로 `operator==(string)`을 지우면 이 식은 `invalid operands to binary expression ('Book' and 'const char[11]')` 오류로 컴파일되지 않는다.

코드를 더 정확하게 만들려면 다음 세 가지를 고려할 수 있다.

- **비교하는 멤버:** `main()`의 주석은 제목, 가격, 쪽수를 모두 비교한다고 하지만 `operator==(Book)`은 제목만 비교한다. 이 `main()`에서는 두 책의 제목이 달라 출력이 맞지만, `Book c("명품 C++", 10000, 100);`처럼 제목만 같고 가격과 쪽수가 다른 책도 `a == c`에서 같은 책으로 판단된다. 주석대로 비교하려면 `return title == op.title && price == op.price && pages == op.pages;`로 쓴다.
- **매개변수 전달 방식:** 두 함수는 `string`과 `Book`을 값으로 받으므로 호출할 때마다 문자열과 객체가 복사된다. 비교 연산자는 피연산자를 바꾸지 않으므로 보통 `bool operator==(const Book& op) const`처럼 `const` 참조로 받고 `const` 멤버 함수로 선언한다([7장 3.4절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#34-비교-연산자)).
- **조건문의 단순화:** `if (조건) return true; else return false;`는 `return this->title == op;`처럼 비교식의 값을 그대로 리턴하는 것과 같다.

참조 질문의 `!=` 연산자는 이미 정의한 `==`를 이용하여 그 결과를 뒤집는 방식으로 구현할 수 있다.

```cpp
bool operator != (Book op) {
    return !(*this == op);
}
```

`*this == op`는 `this->operator==(op)`를 호출하므로, `==`의 비교 기준을 바꾸면 `!=`도 따라 바뀌어 두 연산자의 결과가 항상 반대가 된다. 이 함수를 Q2의 `Book` 클래스에 추가하면 `a != b`는 `true`이고, 위의 `c`에 대해 `a != c`는 `false`이다. 문자열과 비교하는 `!=`도 `bool operator != (string op) { return !(*this == op); }`로 같은 방식으로 만든다.

### 3.3 실행 결과와 검토

```text
명품 C++ 입니다.
두 책은 다른 책입니다.
```

출력은 문제의 실행 예시와 같다. 두 번째 줄은 `a`와 `b`의 제목이 달라서 나온 결과이며, 제목이 같고 가격만 다른 두 책으로 실행하면 현재 코드는 `두 책이 같은 책입니다.`를 출력한다.

## 4. Q3. 여러 연산자를 중복한 MyString 클래스

### 4.1 요구사항

연산자 중복을 활용하는 코드를 교재와 다른 예로 자유롭게 작성한다. 풀이는 C 문자열을 동적 메모리에 저장하는 `MyString` 클래스를 만들고 다음 여섯 연산자를 멤버 함수로 중복한다.

| 연산자 | 연산자 함수 | 하는 일 |
|:-----|:-----|:-----|
| `=` | `MyString& operator=(const MyString&)` | 깊은 복사로 대입하고 `*this`의 참조를 리턴한다 |
| `+` | `MyString operator+(const MyString&)` | 두 문자열을 이은 새 객체를 값으로 리턴한다 |
| `<` | `bool operator<(const MyString&)` | `strcmp()`로 사전식 순서를 비교한다 |
| `==` | `bool operator==(const MyString&)` | `strcmp()`로 두 문자열이 같은지 비교한다 |
| `+=` | `MyString& operator+=(const MyString&)` | 문자열을 뒤에 이어 붙이고 `*this`의 참조를 리턴한다 |
| `[]` | `char& operator[](int)` | 인덱스의 범위를 검사한 뒤 그 위치 문자의 참조를 리턴한다 |

*표 4. Q3에서 중복한 연산자*

### 4.2 설계와 해결 방법

입출력을 위해 `<iostream>`을, `strlen()`, `strcpy()`, `strcat()`, `strcmp()`를 위해 `<cstring>`을 포함한다. `MyString` 클래스는 문자열 하나를 표현하며, 문자열을 저장하는 동적 배열의 포인터 `str`과 문자열의 길이 `len`을 `private` 멤버 변수로 둔다. `public` 아래에는 생성자, 복사 생성자, 소멸자, 여섯 연산자 함수, `show()`를 둔다.

- **생성자:** `const char*`를 받아(디폴트 값 `""`) `strlen()`으로 길이를 구하고, 널 문자까지 담을 수 있게 `len + 1`개의 `char`를 할당하여 `strcpy()`로 복사한다.
- **복사 생성자:** 다른 객체의 포인터를 그대로 복사하지 않고, 새 메모리를 할당하여 문자열의 내용을 복사하는 깊은 복사를 한다.
- **소멸자:** 할당한 배열을 `delete[]`로 해제한다.
- **`operator=`:** `this == &s`로 자기 자신을 대입하는 경우를 먼저 걸러 낸다. 그다음 기존 배열을 해제하고 새 배열을 할당하여 복사하며, `*this`의 참조를 리턴하여 `s1 = s2 = s3` 같은 연쇄를 가능하게 한다. 자기 대입을 거르지 않으면 `s1 = s1;`에서 자신의 배열을 먼저 해제한 뒤 해제된 배열을 읽게 된다.
- **`operator+`:** 두 길이의 합에 1을 더한 크기의 임시 배열에 두 문자열을 차례로 복사하고, 그 배열로 결과 객체 `result`를 만든 뒤 임시 배열을 해제하고 `result`를 값으로 리턴한다. 두 피연산자는 바뀌지 않는다.
- **`operator<`, `operator==`:** `strcmp()`가 첫 번째 문자열이 사전식으로 앞이면 음수를, 두 문자열이 같으면 0을 리턴하는 성질을 이용한다.
- **`operator+=`:** `+`와 같은 방법으로 이은 문자열을 만들되, 기존 배열을 해제하고 `str`이 새 배열을 가리키게 하여 객체 자신을 바꾼다.
- **`operator[]`:** 인덱스가 0 이상 `len` 미만이 아니면 `Index out of range`를 출력하고 `exit(1)`로 프로그램을 끝낸다. 범위 안이면 `str[index]`의 참조를 리턴하므로 `s2[0] = 'w';`처럼 문자를 바꾸는 데에도 쓸 수 있다([7장 6절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#6-첨자-연산자)).
- **`show()`:** `str`로 `std::string`을 만들어 리턴하여 `cout`으로 출력할 수 있게 한다.

생성자에서 `new`를, 소멸자에서 `delete[]`를 쓰는 클래스이므로 복사 생성자와 대입 연산자를 함께 정의하였다. 셋 중 하나라도 컴파일러가 만든 기본 버전을 쓰면 두 객체가 같은 배열을 가리키게 되어 이중 해제가 생기므로, 이는 5장의 3의 법칙에 맞는 설계이다([5장 4.5절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#45-깊은-복사)).

`main()`은 `s1`(`"Hello "`), `s2`(`"World!"`), 빈 문자열 `s3`을 만들어 초기 상태를 출력한 뒤, `s3 = s1 + s2;`로 두 문자열을 잇고, `s1 += "C++";`로 문자열을 이어 붙이고, `a < b`로 사전식 순서를 비교하고, `s2[0]`으로 첫 문자를 읽고, `str1 == str2`로 두 문자열이 같은지 비교한다. 프로그램이 끝나면 각 객체의 소멸자가 동적 메모리를 해제한다.

`s1 += "C++";`의 오른쪽 피연산자는 문자열 리터럴이지만 `operator+=`는 `const MyString&`을 받는다. 생성자 `MyString(const char* s = "")`에 `explicit`이 붙어 있지 않으므로 이 생성자가 변환 생성자로 쓰여, 컴파일러가 `"C++"`로 임시 `MyString` 객체를 만들어 넘기고 문장이 끝나면 그 임시 객체를 소멸시킨다. 같은 이유로 `s1 + "!"`도 컴파일된다. 그러나 `"Hi " + s1`은 왼쪽 피연산자가 `MyString`이 아니어서 멤버 함수 `operator+`가 후보가 되지 못하므로 컴파일 오류가 난다. 왼쪽에 문자열 리터럴이 오는 식까지 지원하려면 HW8 Q1처럼 `+`를 비멤버 함수(프렌드 함수)로 중복해야 한다([7장 2.4절](../../Lecture-Notes/Ch07_Friend-Functions-and-Operator-Overloads/Concepts_Lecture.ko.md#24-멤버-함수-vs-프렌드-함수-판단-가이드)).

코드를 더 견고하게 만들려면 다음 네 가지를 고려할 수 있다.

- **헤더 포함:** `exit()`는 `<cstdlib>`에, `std::string`은 `<string>`에 선언되어 있다. macOS의 libc++에서는 `<iostream>`이 이 헤더들을 간접적으로 포함하여 컴파일되지만, 표준은 이를 보장하지 않으므로 직접 포함하는 편이 이식성이 있다.
- **`const` 멤버 함수:** `<`, `==`, `+`, `show()`는 객체를 바꾸지 않지만 `const` 멤버 함수가 아니므로 `const` 객체에는 쓸 수 없다. `const MyString c("Cherry");`일 때 `a < c`는 매개변수가 `const MyString&`이라 컴파일되지만, `c < a`는 `invalid operands to binary expression ('const MyString' and 'MyString')` 오류가 난다. `bool operator<(const MyString& s) const`처럼 선언하면 두 식이 모두 컴파일된다.
- **`exit()`의 사용:** `exit(1)`은 프로그램을 즉시 끝내므로 `main()`의 지역 객체들의 소멸자가 호출되지 않는다. 운영체제가 프로세스의 메모리를 회수하므로 이 프로그램에서 문제가 되지는 않지만, 호출한 쪽이 오류를 처리할 수 있게 하려면 C++의 예외 처리(`throw`와 `try`, `catch`)로 오류를 알리는 방법이 일반적이다.
- **불필요한 검사:** 소멸자와 대입 연산자의 `if(str)`은 `str`이 항상 할당된 배열을 가리키므로 언제나 참이며, `delete[]`는 널 포인터에 대해 아무 일도 하지 않으므로 검사 없이 `delete[] str;`만 써도 된다.

### 4.3 실행 결과와 검토

```text
[초기 상태]
s1: Hello 
s2: World!
s3: 

[연산 수행]
s1 + s2 = Hello World!
s1 += 'C++' = Hello C++
Apple은 Banana보다 사전순으로 앞에 있습니다.
s2의 첫 번째 문자: W
두 문자열이 같습니다.
```

`s1:` 줄의 끝에는 `"Hello "`의 공백이, `s3:` 줄의 끝에는 출력 문자열 `"s3: "`의 공백이 남는다. `s1 += 'C++' = Hello C++` 줄의 작은따옴표는 출력 문자열 `"s1 += 'C++' = "`에 들어 있는 글자이다. `s3`은 `"Hello World!"`가 되고, `s1`은 `"Hello "`에 `"C++"`가 이어져 `"Hello C++"`가 된다. 이 출력에는 나타나지 않지만, macOS의 `leaks --atExit`로 실행하면 누수가 0개로 보고되고 AddressSanitizer(`-fsanitize=address`)로 빌드하여 실행해도 오류가 없으므로, 할당한 배열이 모두 정확히 한 번씩 해제된다.

## 점검 문제

1. **연산자 함수의 직접 호출:** Q1의 `b -= 500;`을 연산자 함수를 직접 호출하는 형태로 쓰라.

   <details>
   <summary>정답</summary>

   `b.operator-=(500);`이다. `operator-=`는 멤버 함수이므로 왼쪽 피연산자 `b`의 멤버 함수로 호출되고, 500이 매개변수 `op`로 전달된다. 이렇게 써도 결과는 `b -= 500;`과 같다.

   </details>

2. **연쇄 결과:** Q1의 `main()` 끝에 `(a += 500) += 100;`과 `a.show();`를 추가하면 마지막 줄에 무엇이 출력되는가? 리턴 타입을 `Book&`로 바꾸면 어떻게 달라지는가?

   <details>
   <summary>정답</summary>

   `a`는 20500원에서 `a += 500`으로 21000원이 되지만, `+= 100`은 리턴된 복사본에 적용되므로 `청춘 21000원 300페이지`가 출력된다. 리턴 타입이 `Book&`이면 두 번째 `+=`도 `a`에 적용되어 `청춘 21100원 300페이지`가 출력된다.

   </details>

3. **비교 기준:** Q2에서 `Book c("명품 C++", 10000, 100);`을 만들고 `a == c`를 검사하면 결과는 무엇인가? `main()`의 주석대로 동작하게 하려면 어떻게 고치는가?

   <details>
   <summary>정답</summary>

   `operator==(Book)`은 제목만 비교하므로 `true`이다. 주석대로 제목, 가격, 쪽수를 모두 비교하려면 함수의 몸체를 `return title == op.title && price == op.price && pages == op.pages;`로 고친다. 그러면 `a == c`는 `false`가 된다.

   </details>

4. **함수의 선택:** Q2에서 `operator==(string)`을 지우면 `a == "명품 C++"`는 어떻게 되는가? `a == string("명품 C++")`는 어떤가?

   <details>
   <summary>정답</summary>

   `a == "명품 C++"`는 컴파일 오류가 난다. 문자열 리터럴이 `Book`이 되려면 `string`을 거치는 사용자 정의 변환이 두 번 필요하지만 암시적 변환에는 한 번만 허용되기 때문이다. `a == string("명품 C++")`는 `string`에서 `Book`으로 생성자를 거치는 변환 한 번이면 되므로 컴파일되고, 제목이 같으므로 `true`이다.

   </details>

5. **왼쪽 피연산자:** Q3에서 `s1 + "!"`는 컴파일되지만 `"Hi " + s1`은 컴파일되지 않는 이유는 무엇이며, 어떻게 고치는가?

   <details>
   <summary>정답</summary>

   멤버 함수 `operator+`는 왼쪽 피연산자의 멤버로 호출되므로 왼쪽이 `MyString`이어야 한다. `s1 + "!"`는 `s1.operator+("!")`이 되고 `"!"`가 변환 생성자로 `MyString`이 되지만, `"Hi " + s1`의 왼쪽은 `const char` 배열이라 멤버 함수를 호출할 수 없다. `friend MyString operator+(const MyString& a, const MyString& s);`처럼 두 피연산자를 모두 매개변수로 받는 비멤버 함수로 중복하면, 왼쪽의 문자열 리터럴도 변환 생성자로 `MyString`이 되어 `"Hi " + s1`이 `"Hi Hello C++"`처럼 동작한다.

   </details>
