## 2. Q1. 자기 참조를 리턴하는 Accumulator 클래스

### 2.1 요구사항

주어진 선언대로 `Accumulator` 클래스를 구현하여, `acc.add(5).add(6).add(7);`처럼 `add()`를 이어서 호출한 문장이 `acc`의 `value`를 10에서 28로 바꾸게 한다. 생성자와 `get()`은 선언에 몸체까지 주어졌으므로, 작성할 부분은 리턴 타입이 `Accumulator&`인 `add(int n)`의 정의이다.

### 2.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Accumulator` 클래스는 값을 누적하는 객체를 표현하며, 누적값을 저장하는 `value`를 `private` 멤버로 두어 바깥에서 직접 접근하지 못하게 한다. 클래스에서 접근 지정자 없이 선언한 멤버는 `private`이다. `public` 아래에는 생성자, `add()`, `get()`을 둔다.

- **생성자:** 매개변수 `value`를 멤버 변수 `value`에 대입한다. 두 이름이 같으므로 `this->value`로 멤버 변수를 가리켜 매개변수와 구분한다.
- **`add(n)`:** 클래스 밖에서 `Accumulator::`를 붙여 정의하였다. `value`에 `n`을 더한 뒤 `*this`, 즉 `add()`를 호출한 객체 자신을 참조로 리턴한다.
- **`get()`:** 현재 `value`를 리턴한다.

`main()`은 초기값 10으로 객체 `acc`를 만들고, `add()`를 이어서 호출하여 5, 6, 7을 차례로 더한 뒤 `get()`으로 최종값 28을 출력한다. `acc.add(5).add(6).add(7)`은 왼쪽부터 계산된다. `acc.add(5)`가 `acc` 자신에 대한 참조를 리턴하므로 그 결과에 대한 `.add(6)`은 다시 `acc`의 멤버 함수 호출이 되고, `.add(7)`도 마찬가지이다. 이처럼 함수가 리턴한 객체에 대해 다음 함수를 이어서 호출하는 방식을 **체이닝(chaining)** 이라 한다. 참조를 리턴하는 함수의 결과는 복사본이 아니라 현존하는 객체 자체를 가리킨다([5장 3.3절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#33-참조-반환)).

리턴 타입의 `&`가 이 동작을 결정한다. `add()`를 `Accumulator add(int n)`으로 선언하여 값으로 리턴하면 컴파일은 되지만 출력은 15이다. 첫 번째 `acc.add(5)`는 `acc`에 작용하여 `value`를 15로 만들지만, 리턴되는 것은 `acc`의 복사본인 임시 객체이다. 따라서 `.add(6)`과 `.add(7)`은 그 임시 객체의 값을 21, 28로 바꾼 뒤 문장이 끝날 때 임시 객체와 함께 사라지고, `acc.get()`은 15를 리턴한다. 리턴 타입을 `void`로 하면 `acc.add(5);`처럼 따로 호출하는 것은 되지만, `void`에는 멤버 함수를 호출할 수 없으므로 연결한 호출은 컴파일 오류가 된다.

### 2.3 실행 결과와 검토

```text
28
```

출력은 문제의 실행 예시와 같다. `leaks --atExit`와 AddressSanitizer, UndefinedBehaviorSanitizer(`-fsanitize=address,undefined`)로 실행해도 오류와 누수가 보고되지 않는다. 이 프로그램은 동적 메모리를 쓰지 않으며, `acc`는 `main()`이 끝날 때 자동으로 소멸한다.

## 3. Q2. 깊은 복사 생성자를 갖춘 Book 클래스

### 3.1 요구사항

책의 제목을 동적으로 할당한 문자열로, 가격을 정수로 저장하는 `Book` 클래스에 대해 네 물음에 답한다. 물음과 답이 있는 곳은 다음과 같다.

| 물음 | 내용 | 답 |
|:-----|:-----|:-----|
| 1) | 생성자, 소멸자, `set()`의 구현 | `Q2.cpp`의 22\~26행, 32\~35행, 36\~43행 |
| 2) | 컴파일러가 추가하는 디폴트 복사 생성자의 코드 | 3.2절의 답 |
| 3) | 복사 생성자를 정의하지 않을 때 생기는 문제 | 3.2절의 답 |
| 4) | 오류가 생기지 않는 복사 생성자의 정의 | `Q2.cpp`의 27~31행 |

*표 2. Q2의 물음과 답의 위치*

### 3.2 설계와 해결 방법

입출력과 문자열 처리를 위해 `<iostream>`과 `<cstring>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Book` 클래스는 책을 표현하며, `private` 멤버로 제목 `title`과 가격 `price`를 둔다. `title`은 제목 문자열을 동적으로 할당받아 그 시작 주소를 저장하는 `char` 포인터이다. `public` 아래에는 생성자, 복사 생성자, 소멸자, `set()`, `show()`를 둔다.

- **생성자:** 받은 제목의 길이에 문자열 끝의 널 문자 자리 하나를 더한 `strlen(title) + 1`바이트를 `new char []`로 할당하고, `strcpy()`로 제목을 복사한 뒤 가격을 저장한다. 매개변수와 멤버의 이름이 같으므로 `this->`로 멤버를 가리킨다.
- **복사 생성자:** 원본 객체 `b`의 가격을 복사하고, `b.title`의 길이만큼 새 메모리를 할당하여 문자열의 내용을 복사한다. 원본과 사본이 각자의 메모리를 가지므로 **깊은 복사(deep copy)** 이며, 물음 4)의 답이다([5장 4.5절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#45-깊은-복사)).
- **소멸자:** `title`이 가리키는 메모리를 `delete []`로 해제하도록 작성하였다. 조건문에 오류가 있으며 3.3절에서 다룬다.
- **`set()`:** 새 제목이 기존 제목보다 길면 기존 메모리를 해제하고 새 길이에 맞게 다시 할당한다. 길지 않으면 기존 메모리를 그대로 쓴다. 이어서 제목을 복사하고 가격을 바꾼다.
- **`show()`:** 제목과 가격을 `명품c++ 10000원` 형식으로 출력한다.

`main()`은 `cpp`를 만들고, `Book java = cpp;`로 `cpp`를 복사하여 `java`를 만든다. 같은 클래스의 객체로 새 객체를 초기화하므로 복사 생성자가 호출된다([5장 4.1절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#41-개념)). 이어서 `java.set()`으로 `java`의 제목과 가격을 바꾸고 두 책을 출력한다. 프로그램이 끝나면 두 객체의 소멸자가 생성의 역순으로 호출된다.

물음 2)에 대한 답은, 컴파일러가 만드는 디폴트 복사 생성자가 멤버 대 멤버 복사를 수행하며 다음 코드와 같다는 것이다.

```cpp
Book::Book(Book& b) {
    title = b.title;
    price = b.price;
}
```

물음 3)에 대한 답은 다음과 같다. 위의 디폴트 복사 생성자에서 `title`은 포인터이므로 얕은 복사만 수행되어 `title`이 가리키는 주소만 복사되고, 동적으로 할당된 내용은 복사되지 않는다. 소멸자가 한 객체의 `title`을 `delete`한 뒤 다른 객체의 `title`을 다시 `delete`하면 같은 메모리를 두 번 삭제하게 되며, 답은 이를 메모리 누수라고 불렀다.

두 답은 다음과 같이 보완할 수 있다.

- **디폴트 복사 생성자의 원형:** 멤버 단위 복사라는 답은 맞다([5장 4.2절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#42-디폴트-복사-생성자)). 다만 표준 C++에서 컴파일러가 암시적으로 선언하는 복사 생성자는 모든 멤버를 `const` 객체에서 복사할 수 있으면 `Book(const Book&)` 형태이며, `char*`와 `int` 멤버는 이 조건을 만족한다. 그래서 디폴트 복사 생성자로는 `const Book` 객체도 복사할 수 있지만, `Book(Book&)`만 정의한 클래스에서는 `const Book` 객체를 복사하면 "no matching constructor" 오류가 난다. 두 객체 사이에서 하는 일, 즉 `title`과 `price`를 그대로 복사하는 일은 같다.
- **문제의 이름:** 같은 메모리를 두 번 해제하는 것은 메모리 누수가 아니라 **이중 해제(double free)** 이다. 메모리 누수는 해제하지 않은 메모리가 남는 것이고, 이중 해제는 이미 해제한 메모리를 다시 해제하는 것으로, 결과가 정의되지 않은 동작이며 대개 프로그램이 비정상 종료된다([5장 4.3절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#43-얕은-복사의-문제)).
- **이 `main()`에서 먼저 생기는 문제:** 이 `main()`에서는 이중 해제보다 앞서 해제된 메모리의 사용이 생긴다. `"명품자바"`는 UTF-8로 12바이트이고 `"명품c++"`는 9바이트이므로, `java.set()`은 `cpp`와 공유하던 메모리를 해제하고 `java`에만 새 메모리를 할당한다. 그러면 `cpp.title`은 해제된 메모리를 가리키는 **댕글링 포인터(dangling pointer)** 가 되고, `cpp.show()`가 그 메모리를 읽는다([4장 4.2절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#42-댕글링-포인터)). 3.3절에서 이 상황을 실제로 실행한 결과를 다룬다.

코드를 더 견고하게 만들려면 다음 세 가지를 고려할 수 있다.

- **`const char*` 매개변수:** 문자열 리터럴의 타입은 `const char[N]`이며, 이를 `char*`로 바꾸는 변환은 C++11 표준에서 삭제되었다. Apple clang은 확장으로 받아들이고 `-Wwritable-strings` 경고를 내지만, Visual Studio 2022의 표준 준수 모드(`/permissive-`)는 이 변환을 오류로 처리한다. 과제 안내문이 Visual Studio 2022에서 `const`를 추가해야 할 수 있다고 한 것은 이 변환 때문이다. 생성자와 `set()`의 매개변수를 `const char* title`로 바꾸면 두 경고가 사라지고 `-std=c++11`에서도 경고 없이 컴파일된다.
- **`const` 참조를 받는 복사 생성자:** 복사 생성자는 원본을 바꾸지 않으므로 `Book(const Book& b)`로 선언하면 `const` 객체와 임시 객체로부터도 복사할 수 있다([5장 5.3절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#53-복사-생성자의-매개변수는-참조)).
- **대입 연산자:** 깊은 복사 생성자가 있어도 이미 만든 객체끼리 `java = cpp;`로 치환하면 컴파일러가 만든 디폴트 대입 연산자가 포인터 값만 복사한다. 소멸자가 올바르게 해제하는 `Book`으로 시험하면 AddressSanitizer가 이중 해제를 보고하고, `java`가 원래 가리키던 메모리는 누수된다. 포인터 멤버를 가진 클래스는 복사 생성자, 소멸자와 함께 대입 연산자도 작성해야 한다([5장 2.3절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#23-객체-치환)).

### 3.3 실행 결과와 검토

```text
명품c++ 10000원
명품자바 12000원
```

`java`의 제목을 바꾼 뒤에도 `cpp`의 제목이 그대로인 것은 복사 생성자가 깊은 복사를 했기 때문이다. `-Wall`의 경고 두 개는 47행과 49행에서 문자열 리터럴을 `char*` 매개변수에 넘기기 때문이며, 3.2절처럼 `const char*`로 고치면 사라진다.

메모리 검사의 결과는 다음과 같다.

- **AddressSanitizer와 UndefinedBehaviorSanitizer:** 오류가 보고되지 않는다.
- **`leaks --atExit`:** 블록 2개, 합계 64바이트의 누수가 보고된다. 하나는 생성자가 `cpp`의 제목에 할당한 메모리이고, 다른 하나는 `set()`이 `java`의 새 제목에 할당한 메모리이다. 복사 생성자가 `java`에 할당한 메모리는 `set()`이 해제했으므로 남지 않는다.

누수의 원인은 32~35행 소멸자의 조건문 `if (!title)`이다. 이 조건은 `title`이 널 포인터일 때만 참이므로, 제목이 할당되어 있는 보통의 경우에는 `delete []`가 실행되지 않는다. 널 포인터를 검사하려면 조건이 `if (title)`이어야 하지만, `delete []`에 널 포인터를 넘기면 아무 일도 하지 않으므로 조건 없이 `delete [] title;`만 쓰면 된다([4장 4.3절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#43-소멸자의-책임)). 이렇게 고치면 출력은 같고 `leaks`는 누수를 보고하지 않는다.

물음 3)의 상황은 27~31행의 복사 생성자와 17행의 선언을 지우고 디폴트 복사 생성자로 실행하여 확인할 수 있다.

- **AddressSanitizer:** `cpp.show()`가 `set()`에서 해제된 메모리를 읽는다는 heap-use-after-free를 보고한다.
- **ASan 없이 실행:** macOS에서는 첫 줄이 `명품자바 10000원`으로 출력될 수 있다. 할당기가 `set()`에서 해제된 블록을 `java`의 새 제목에 다시 내주어 `cpp.title`이 그 문자열을 가리켰기 때문이며, 정의되지 않은 동작이므로 결과는 환경에 따라 다르다.
- **소멸자도 고친 경우:** 프로그램이 끝날 때 `cpp`의 소멸자가 이미 해제된 메모리를 다시 해제한다. AddressSanitizer는 이를 attempting double-free로 보고하고, ASan 없이 실행하면 출력 뒤에 프로그램이 비정상 종료된다.
- **풀이의 소멸자 그대로인 경우:** 소멸자가 아무것도 해제하지 않으므로 이중 해제는 나타나지 않지만, 해제된 메모리의 사용은 그대로 생긴다.

## 요약

| 개념 | 핵심 요약 |
|:-----|:-----|
| 참조 리턴 | `Accumulator&`를 리턴하는 `add()`는 `*this`, 즉 호출한 객체 자신을 돌려주므로 `acc.add(5).add(6).add(7)`의 세 호출이 모두 `acc`에 작용한다. |
| 값 리턴과의 차이 | `add()`가 값으로 리턴하면 두 번째 호출부터는 임시 복사본에 작용하므로 결과는 28이 아니라 15이다. |
| 디폴트 복사 생성자 | 복사 생성자를 정의하지 않으면 컴파일러가 멤버 단위로 복사하는 복사 생성자를 만들며, 포인터 멤버는 주소만 복사된다. |
| 얕은 복사의 문제 | 두 객체가 같은 메모리를 가리키면 해제된 메모리의 사용이나 이중 해제가 생기며, 이는 메모리 누수가 아니라 정의되지 않은 동작이다. |
| 깊은 복사 | 복사 생성자에서 `new char [strlen(b.title) + 1]`로 새 메모리를 할당하고 `strcpy()`로 내용을 복사한다. |
| 소멸자의 조건 | `if (!title) delete [] title;`은 아무것도 해제하지 않아 누수를 만들며, `delete []`는 널 포인터에 안전하므로 조건 없이 해제한다. |
| 문자열 리터럴과 `const` | 문자열 리터럴을 받는 매개변수는 `const char*`로 선언해야 C++11 이후의 표준에 맞는다. |

## 점검 문제

1. **값 리턴:** Q1의 `add()`가 `Accumulator add(int n)`처럼 값으로 리턴하도록 바꾸면 `acc.add(5).add(6).add(7);` 다음의 `acc.get()`은 얼마인가?

   <details>
   <summary>정답</summary>

   15이다. 첫 번째 `add(5)`만 `acc`에 작용하고, 그 리턴값은 `acc`의 복사본인 임시 객체이므로 `add(6)`과 `add(7)`은 임시 객체의 값을 바꾼다. 임시 객체는 문장이 끝날 때 사라진다.

   </details>

2. **리턴 문:** Q1의 `return *this;`를 `return this;`로 쓰면 어떻게 되는가?

   <details>
   <summary>정답</summary>

   컴파일 오류가 난다. `this`는 `Accumulator*` 타입의 포인터이므로 리턴 타입 `Accumulator&`에 묶을 수 없다. 참조를 리턴하려면 포인터가 가리키는 객체인 `*this`를 리턴해야 한다.

   </details>

3. **공유 메모리:** Q2에서 복사 생성자를 지우고 `java.set("명품자바", 12000);`을 `java.set("자바", 12000);`으로 바꾸면 출력은 어떻게 되는가?

   <details>
   <summary>정답</summary>

   첫 줄은 `명품c++ 10000원`이 아니라 `자바 10000원`이고, 둘째 줄은 `자바 12000원`이다. `"자바"`는 6바이트로 기존 제목 9바이트보다 짧으므로 `set()`은 다시 할당하지 않고 공유 메모리에 그대로 복사한다. 두 객체의 `title`이 같은 메모리를 가리키므로 `cpp`의 제목도 바뀐다.

   </details>

4. **소멸 순서:** Q2에서 복사 생성자를 지우고 소멸자를 `delete [] title;`로 고친 뒤 `set()` 호출도 지우면, 프로그램이 끝날 때 무슨 일이 생기는가?

   <details>
   <summary>정답</summary>

   객체는 생성의 역순으로 소멸하므로 `java`의 소멸자가 먼저 공유 메모리를 해제하고, 이어서 `cpp`의 소멸자가 같은 메모리를 다시 해제한다. 이중 해제이며 정의되지 않은 동작이다. AddressSanitizer는 `~Book()`에서의 attempting double-free를 보고한다.

   </details>

5. **할당 크기:** Q2의 생성자가 `"명품c++"`에 대해 할당하는 바이트 수와, `strlen()`의 결과에 1을 더하는 이유를 쓰라.

   <details>
   <summary>정답</summary>

   UTF-8에서 한글 두 글자는 6바이트, `c++`는 3바이트이므로 `strlen()`은 9이고, 할당하는 크기는 10바이트이다. `strlen()`은 문자열 끝의 널 문자를 세지 않지만 `strcpy()`는 널 문자까지 복사하므로 그 자리 1바이트를 더한다.

   </details>
