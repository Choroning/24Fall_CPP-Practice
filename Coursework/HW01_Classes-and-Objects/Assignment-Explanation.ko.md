## 2. Q1. 은행 계좌 Account 클래스

### 2.1 요구사항

계좌의 주인, 계좌 번호, 잔액의 세 멤버 변수로 계좌 하나를 표현하는 `Account` 클래스를 작성한다. 주어진 `main()`이 사용하는 멤버는 다음과 같다.

| `main()`의 사용 | 필요한 멤버 | 하는 일 |
|:-----|:-----|:-----|
| `Account a("kitae", 1, 5000);` | 매개변수 3개 생성자 | 주인, 계좌 번호, 초기 잔액으로 객체를 초기화한다 |
| `a.deposit(50000);` | `void deposit(int)` | 잔액에 입금액을 더한다 |
| `a.getOwner()` | `string getOwner()` | 계좌 주인의 이름을 리턴한다 |
| `a.inquiry()` | `int inquiry()` | 현재 잔액을 리턴한다 |
| `int money = a.withdraw(20000);` | `int withdraw(int)` | 잔액에서 출금액을 빼고 출금한 금액을 리턴한다 |

*표 1. Q1의 `main()`이 요구하는 멤버*

### 2.2 설계와 해결 방법

입출력과 문자열 처리를 위해 `<iostream>`과 `<string>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Account` 클래스는 은행 계좌를 표현하며, `public` 접근 지정자 아래에 계좌 주인의 이름 `name`, 계좌 번호 `id`, 잔액 `balance`를 둔다. 클래스 선언부에는 기본 생성자, 매개변수 3개 생성자, `getOwner()`, `deposit()`, `withdraw()`, `inquiry()`의 원형만 두고, 몸체는 클래스 밖에서 `Account::`를 붙여 정의하여 선언과 정의를 분리했다([3장 2.3절](../../Lecture-Notes/Ch03_Classes-and-Objects/Concepts_Lecture.ko.md#23-멤버-함수)).

- **매개변수 3개 생성자:** 이름, 계좌 번호, 초기 잔액을 받아 각 멤버 변수에 대입한다.
- **`getOwner()`:** 계좌 주인의 이름을 리턴한다.
- **`deposit(m)`:** 입금액 `m`을 잔액에 더한다.
- **`withdraw(m)`:** 잔액에서 출금액 `m`을 빼고, 출금한 금액 `m`을 리턴한다.
- **`inquiry()`:** 현재 잔액을 리턴한다.

`main()`은 이름 `"kitae"`, 계좌 번호 1, 초기 잔액 5000으로 객체 `a`를 만들고, 50000원을 입금한 뒤 주인의 이름과 잔액을 출력한다. 이어서 20000원을 출금하여 그 금액을 `money`에 저장하고, 갱신된 잔액을 다시 출력한다. 잔액은 5000, 55000, 35000으로 바뀐다.

코드를 더 견고하게 만들려면 다음 세 가지를 고려할 수 있다.

- **선언만 한 기본 생성자:** `Account();`는 선언만 있고 정의가 없다. 이 `main()`은 기본 생성자를 호출하지 않으므로 컴파일과 링크가 모두 성공한다. 그러나 `Account b;`처럼 기본 생성자를 쓰는 코드가 하나라도 생기면, 컴파일은 되지만 링크 단계에서 `Account::Account()`의 정의를 찾지 못한다는 오류가 난다. 쓰지 않을 생성자는 선언하지 않거나, 쓸 계획이면 정의까지 작성해야 한다([3장 4.5절](../../Lecture-Notes/Ch03_Classes-and-Objects/Concepts_Lecture.ko.md#45-기본-생성자)).
- **`public` 멤버 변수:** 문제는 접근 제어를 정하지 않았으므로 `public`이어도 요구사항에 어긋나지 않는다. 다만 `main()`은 멤버 함수만 쓰므로, 세 멤버 변수를 `private`으로 옮겨도 `main()`을 고칠 필요가 없다. 잔액을 바깥에서 `a.balance = -100;`처럼 직접 바꾸지 못하게 하려면 `private`으로 두는 편이 캡슐화 원칙에 맞다([3장 2.4절](../../Lecture-Notes/Ch03_Classes-and-Objects/Concepts_Lecture.ko.md#24-접근-지정자)).
- **잔액보다 큰 출금:** `withdraw()`는 잔액을 검사하지 않으므로 잔액보다 큰 금액을 요청하면 잔액이 음수가 된다. 교재의 주석은 `withdraw()`가 실제로 출금한 금액을 리턴한다고 하므로, 잔액이 부족할 때 출금하지 않고 0을 리턴하거나 잔액만큼만 출금하고 그 금액을 리턴하도록 바꿀 수 있다.

### 2.3 실행 결과와 검토

```text
kitae의 잔액은 55000
kitae의 잔액은 35000
```

`-Wall`로 컴파일하면 `main()`이 `withdraw()`의 리턴값을 `money`에 저장하고 쓰지 않으므로 `-Wunused-variable` 경고가 나온다. 이 `main()`은 교재가 준 코드이다.

## 3. Q2. 랜덤 정수를 발생시키는 Random 클래스

### 3.1 요구사항

생성자와 `next()`, `nextInRange()`의 세 멤버 함수를 가진 `Random` 클래스를 작성한다. `next()`는 0 이상 `RAND_MAX` 이하의 랜덤 정수를, `nextInRange(s, f)`는 `s` 이상 `f` 이하의 랜덤 정수를 리턴한다. 주어진 `main()`은 각 함수로 랜덤 정수를 10개씩 출력한다.

### 3.2 설계와 해결 방법

난수 생성과 입출력을 위해 `<iostream>`, `<cstdlib>`, `<ctime>`을 포함한다. `<ctime>`은 난수를 생성할 때 현재 시각을 시드로 써서 실행할 때마다 다른 난수가 나오게 하기 위해 쓴다. `Random` 클래스는 난수 생성기를 표현하며, `public` 아래에 생성자와 두 멤버 함수의 원형을 두고 몸체는 클래스 밖에서 정의했다.

- **생성자:** `srand((unsigned)time(0));`으로 현재 시각을 시드로 정한다. `time(0)`은 대부분의 시스템에서 1970-01-01 00:00:00 UTC부터 지난 초 수이므로 실행할 때마다 다른 시드가 된다.
- **`next()`:** `rand()`를 호출하여 0 이상 `RAND_MAX` 이하의 난수를 리턴한다.
- **`nextInRange(s, f)`:** `rand() % (f - s + 1)`이 0 이상 `f - s` 이하의 값이므로, 여기에 `s`를 더하면 `s` 이상 `f` 이하의 값이 된다. `nextInRange(2, 4)`에서는 `rand() % 3 + 2`로 2, 3, 4 중 하나가 나온다.

`main()`은 `Random` 객체 `r`을 만들고, 첫 번째 안내 문구를 출력한 뒤 `for` 문으로 10번 반복하며 `next()`로 만든 난수를 출력한다. 이어서 두 번째 안내 문구를 출력하고, 다시 10번 반복하며 `nextInRange(2, 4)`로 2에서 4 사이의 난수를 출력한다.

다음 두 가지는 이 설계의 성질이다.

- **시드는 프로그램 전체에 하나이다:** `srand()`는 객체마다가 아니라 프로그램 전체의 난수열을 정한다. 같은 초 안에 `Random` 객체를 두 개 만들면 두 번째 생성자가 같은 시드로 난수열을 처음으로 되돌리므로, 두 객체가 이어서 같은 수를 낼 수 있다. 시드를 한 번만 정하려면 HW6 Q3처럼 시드 설정을 static 멤버 함수로 분리하여 `main()`의 처음에 한 번 호출하는 방법이 있다.
- **나머지 연산의 치우침:** `RAND_MAX + 1`이 구간의 길이 `f - s + 1`의 배수가 아니면, 나머지 연산으로 만든 값 중 작은 값이 약간 더 자주 나온다. `RAND_MAX`가 32767이고 구간의 길이가 3이면 32768을 3으로 나눈 나머지가 2이므로, 2와 3이 4보다 각각 한 번씩 더 많은 경우의 수를 가진다. 이 과제의 용도에서는 무시할 수 있는 차이이며, 엄밀한 균등 분포가 필요하면 C++11의 `<random>` 라이브러리(`std::mt19937`과 `std::uniform_int_distribution`)를 쓴다.

### 3.3 실행 결과와 검토

macOS에서 실행한 결과의 한 예는 다음과 같다.

```text
-- 0에서 2147483647까지의 랜덤 정수 10개 --
324124383 1539976289 908575579 1821026083 48439937 233718946 366735059 438069723 1063892545 893158893 

-- 2에서 4까지의 랜덤 정수 10개 --
2 3 3 2 2 2 3 2 2 2 
```

Windows의 Visual C++에서 실행하면 첫 줄이 `-- 0에서 32767까지의 랜덤 정수 10개 --`이고 다섯 자리 이하의 수가 나온다. `RAND_MAX`의 값은 C 표준이 최소 32767이라고만 정하며, Microsoft Visual C++의 런타임은 32767, macOS와 Linux의 C 라이브러리는 2147483647($2^{31} - 1$)로 정의한다. 따라서 같은 코드도 플랫폼에 따라 첫 줄과 수의 범위가 다르다. 두 번째 줄의 수는 어느 플랫폼에서나 2, 3, 4 중 하나이다. 각 줄 끝에 공백이 하나 남는 것은 `cout << n << ' ';`이 수마다 뒤에 공백을 붙이기 때문이다.

## 4. Q3. 접근 제어와 get/set 함수를 갖춘 Point 클래스

### 4.1 요구사항

`private` 좌표 `x`, `y`를 가진 `Point` 클래스를 작성하고, 사용자가 입력한 값으로 `p2`의 좌표를 정한 뒤 두 점의 좌표를 출력한다. 멤버 함수마다 정의하는 위치가 정해져 있다.

| 멤버 | 정의 위치 |
|:-----|:-----|
| 기본 생성자 (`x`, `y`를 0으로) | 클래스 안에서 선언과 동시에 정의 |
| 인자 2개 생성자 | 클래스 밖에서 정의 |
| `showP()` | 클래스 밖에서 정의 |
| `getX()`, `setX()` | 클래스 안에서 선언과 동시에 정의 |
| `getY()`, `setY()` | 클래스 밖에서 정의 |

*표 2. Q3의 멤버와 정의 위치*

### 4.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함한다. `Point` 클래스는 2차원 평면 위의 점을 표현하며, `private` 아래에 좌표 `x`, `y`를 두고 `public` 아래에 두 생성자와 `showP()`, `getX()`, `setX()`, `getY()`, `setY()`를 둔다.

- **기본 생성자:** `x = y = 0;`으로 두 좌표를 0으로 초기화한다. 대입 연산자는 오른쪽부터 결합하므로 `y = 0`이 먼저 실행되고 그 값 0이 `x`에 대입된다.
- **인자 2개 생성자:** 받은 두 좌표를 `x`, `y`에 대입한다. 이 `main()`에서는 쓰이지 않지만 요구사항에 따라 클래스 밖에서 정의했다.
- **`showP()`:** `getX()`와 `getY()`로 좌표를 가져와 `x: 0, y: 0` 형식으로 출력한다. 멤버 함수 안에서는 `x`, `y`에 직접 접근할 수도 있지만, get 함수를 거치면 좌표를 읽는 방법이 한 곳으로 모인다.
- **get/set 함수:** `getX()`와 `setX()`는 클래스 안에서, `getY()`와 `setY()`는 클래스 밖에서 정의하여 두 방식을 함께 보인다. 클래스 안에서 몸체까지 정의한 멤버 함수는 자동으로 인라인 함수로 취급되며, 클래스 밖에서 정의한 멤버 함수는 `inline`을 붙이지 않는 한 일반 함수로 컴파일된다([3장 5절](../../Lecture-Notes/Ch03_Classes-and-Objects/Concepts_Lecture.ko.md#5-인라인-함수)). 두 방식은 동작은 같고, 코드를 읽는 쪽에서 클래스 선언부만 보고 인터페이스를 파악하기 쉬운지가 다르다.

`main()`은 기본 생성자로 `p1`과 `p2`를 만들어 두 점 모두 (0, 0)에서 시작한다. 입력을 받을 임시 변수 `temp`를 두고, `p2`의 x 좌표를 입력받아 `setX()`로, y 좌표를 입력받아 `setY()`로 정한다. 마지막으로 `p1`과 `p2`의 좌표를 `showP()`로 출력한다. `x`와 `y`가 `private`이므로 `main()`에서 `p2.x = temp;`처럼 쓰면 컴파일 오류가 나며, 그래서 set 함수가 필요하다([3장 9.2절](../../Lecture-Notes/Ch03_Classes-and-Objects/Concepts_Lecture.ko.md#92-클래스-외부에서-private-멤버에-접근)).

### 4.3 실행 결과와 검토

`-3`과 `4`를 입력하면 다음과 같이 출력된다.

```text
Input p2.x: -3
Input p2.y: 4
p1. x: 0, y: 0
p2. x: -3, y: 4
```

입력을 파일이나 파이프로 넣으면 입력한 값이 화면에 나타나지 않으므로 `Input p2.x: Input p2.y: p1. x: 0, y: 0`처럼 프롬프트가 한 줄에 이어진다. 출력 자체는 같다. 정수가 아닌 값(예: `a`)을 입력하면 `cin`이 실패 상태가 되어 `temp`에 0이 저장되고(C++11 이후), 다음 입력도 읽히지 않는다.

|:-----|:-----|
| 선언과 정의의 분리 | 클래스 선언부에는 멤버의 원형만 두고, 몸체는 클래스 밖에서 `클래스명::함수명`으로 정의한다. |
| 매개변수가 있는 생성자 | `Account a("kitae", 1, 5000);`처럼 객체를 만들 때 인자를 받아 멤버 변수를 초기화한다. |
| 정의하지 않은 생성자 | 선언만 한 생성자는 호출하지 않으면 문제가 없지만, 호출하는 순간 링크 오류가 된다. |
| 랜덤 정수의 범위 | `rand() % (f - s + 1) + s`는 `s` 이상 `f` 이하의 값을 만들며, 시드는 `srand((unsigned)time(0))`으로 정한다. |
| `RAND_MAX` | 표준은 최소 32767만 정하므로 MSVC는 32767, macOS와 Linux는 2147483647로 플랫폼마다 다르다. |
| 접근 제어와 get/set | `private` 멤버는 클래스 밖에서 직접 접근할 수 없으므로 `public` get/set 함수로 읽고 바꾼다. |
| 클래스 안의 정의 | 클래스 안에서 몸체까지 정의한 멤버 함수는 자동으로 인라인 함수로 취급된다. |

## 점검 문제

1. **링크 오류:** Q1의 `main()`에 `Account b;`를 추가하면 컴파일과 링크 중 어느 단계에서 어떤 오류가 나는가?

   <details>
   <summary>정답</summary>

   `Account();`라는 선언이 있으므로 컴파일은 성공한다. 그러나 기본 생성자의 정의가 어디에도 없으므로 링크 단계에서 `Account::Account()`라는 기호를 찾지 못한다는 오류가 난다. 기본 생성자를 정의하거나 `Account b;`를 쓰지 않아야 한다.

   </details>

2. **잔액 추적:** Q1에서 `a.withdraw(60000);`을 한 번 더 호출하면 잔액과 리턴값은 얼마인가? 잔액이 음수가 되지 않게 하려면 어떻게 고치는가?

   <details>
   <summary>정답</summary>

   잔액은 35000 - 60000 = -25000이 되고 리턴값은 60000이다. `if (m > balance) return 0;`처럼 잔액이 부족하면 출금하지 않고 0을 리턴하게 하거나, 잔액만큼만 출금하고 그 금액을 리턴하게 고친다.

   </details>

3. **범위 계산:** Q2의 `nextInRange(-5, 5)`가 리턴할 수 있는 값의 범위와 경우의 수를 쓰라.

   <details>
   <summary>정답</summary>

   `f - s + 1`이 11이므로 `rand() % 11`은 0 이상 10 이하이고, 여기에 -5를 더하면 -5 이상 5 이하이다. 경우의 수는 11가지이다.

   </details>

4. **같은 시드:** Q2의 `main()`에서 `Random r1, r2;`처럼 객체 두 개를 연달아 만들고 `r1.next()`와 `r2.next()`를 한 번씩 호출하면 두 값은 같은가?

   <details>
   <summary>정답</summary>

   같지 않다. 두 생성자가 같은 초 안에 실행되면 `r2`의 생성자가 같은 시드로 난수열을 처음으로 되돌리지만, 그 뒤의 `r1.next()`와 `r2.next()`는 하나의 난수열에서 차례로 첫째, 둘째 값을 꺼낸다. 난수열은 객체가 아니라 프로그램 전체에 하나이기 때문이다. 다만 `r1`을 만들고 `next()`를 호출한 뒤 같은 초 안에 `r2`를 만들면, `r2.next()`는 `r1`의 첫 값과 같은 값을 다시 낸다.

   </details>

5. **접근 제어:** Q3의 `main()`에서 `cout << p2.x;`라고 쓰면 어떻게 되며, 같은 일을 하려면 어떻게 써야 하는가?

   <details>
   <summary>정답</summary>

   `x`는 `private` 멤버이므로 클래스 밖인 `main()`에서 접근할 수 없어 컴파일 오류가 난다. `cout << p2.getX();`처럼 `public` get 함수를 거쳐 읽어야 한다.

   </details>
