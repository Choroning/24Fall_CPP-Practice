## 2. Q1. 디폴트 매개변수를 갖는 Person 생성자

### 2.1 요구사항

[실습 2-1]의 세 생성자 `Person()`, `Person(int id, string name)`, `Person(int id, string name, double weight)`를 디폴트 매개변수를 갖는 생성자 하나로 바꾸어, 주어진 `main()`의 세 객체 생성을 모두 처리한다. 실행 예시에서 정해지는 세 객체의 값은 다음과 같다.

| `main()`의 생성 | 넘기는 인자 | `id` | `weight` | `name` |
|:-----|:-----|-----:|-----:|:-----|
| `grace` | 없음 | 1 | 20.5 | `"Grace"` |
| `ashley(2, "Ashley")` | `id`, `name` | 2 | 20.5 | `"Ashley"` |
| `helen(3, "Helen", 32.5)` | `id`, `name`, `weight` | 3 | 32.5 | `"Helen"` |

*표 2. Q1의 세 객체와 멤버의 값*

### 2.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 이름 공간을 기본으로 쓴다. `Person` 클래스는 회원을 표현하며 `private` 멤버로 `id`, `weight`, `name`을 둔다. 생성자는 매개변수 `id`, `name`, `weight`를 이 순서로 받으며, 각각 디폴트 값 1, `"Grace"`, 20.5를 갖는다. 받은 값은 `this` 포인터로 멤버 변수에 대입한다. `show()`는 `id`, `weight`, `name`을 공백으로 구분하여 순서대로 출력한다.

`main()`은 서로 다른 개수의 인자로 세 `Person` 객체를 만든다. `grace`는 인자 없이 만들어져 세 디폴트 값을 모두 쓰고, `ashley`는 `id`와 `name`만 넘겨 `weight`에 디폴트 값을 쓰며, `helen`은 세 값을 모두 넘긴다. 넘긴 인자는 왼쪽 매개변수부터 채워지고, 남은 매개변수에 디폴트 값이 들어가므로 세 호출은 `Person(1, "Grace", 20.5)`, `Person(2, "Ashley", 20.5)`, `Person(3, "Helen", 32.5)`와 같다([6장 2.1절](../../Lecture-Notes/Ch06_Overloading-and-Static-Members/Concepts_Lecture.ko.md#21-문법)). 이어서 각 객체의 `show()`로 정보를 출력한다.

매개변수의 순서는 멤버 변수의 선언 순서(`id`, `weight`, `name`)가 아니라 `main()`의 호출에 맞춘 `id`, `name`, `weight`이다. 인자는 왼쪽부터 채워지므로, `ashley(2, "Ashley")`처럼 무게만 생략하려면 `weight`가 맨 오른쪽에 있어야 한다.

다음 두 가지는 디폴트 매개변수의 규칙에 따른 이 설계의 성질이다.

- **디폴트 값은 선언에만 쓴다:** 16행의 선언에 디폴트 값을 쓰고, 20행의 클래스 밖 정의에는 쓰지 않았다. 정의에도 `int id = 1`처럼 다시 쓰면 Apple clang은 "redefinition of default argument" 오류를 낸다([6장 2.2절](../../Lecture-Notes/Ch06_Overloading-and-Static-Members/Concepts_Lecture.ko.md#22-선언과-정의의-분리)).
- **원래의 중복 생성자와 함께 둘 수 없다:** 디폴트 매개변수를 갖는 생성자와 [실습 2-1]의 `Person()`을 함께 두면 `Person grace;`가 두 생성자에 모두 일치하여 "call to constructor of 'Person' is ambiguous" 오류가 난다. 그래서 세 생성자를 하나로 합칠 때는 원래의 생성자를 모두 지운다([6장 2.4절](../../Lecture-Notes/Ch06_Overloading-and-Static-Members/Concepts_Lecture.ko.md#24-디폴트-매개변수로-오버로딩-간소화)).

> **주의:** `string`을 쓰지만 `<string>`을 포함하지 않았다. macOS의 libc++에서는 `<iostream>`이 내부에서 `<string>`을 포함하므로 컴파일되지만, 표준은 이를 보장하지 않으므로 표준 라이브러리의 구현에 따라 컴파일되지 않을 수 있다. `string`을 쓰는 파일은 `#include <string>`을 직접 쓴다. Q2도 마찬가지이다.

### 2.3 실행 결과와 검토

```text
1 20.5 Grace
2 20.5 Ashley
3 32.5 Helen
```

출력은 강의자료의 실행 예시, 제출한 실행 화면과 같다. `leaks --atExit`와 `-fsanitize=address,undefined`로 실행해도 오류와 누수가 보고되지 않는다. `ashley`의 무게 20.5는 넘기지 않은 세 번째 인자 자리에 디폴트 값이 들어간 결과이다.

## 3. Q2. static 멤버로 회원 수를 세는 Person 클래스

### 3.1 요구사항

`Person` 클래스에 현재 회원 수를 저장하는 `private` static 멤버 변수 `numPerson`을 추가하고, 생성자에서 늘리고 소멸자에서 줄인다. 수정된 `main()`은 객체 두 개를 만들고, 원소가 두 개인 동적 배열을 만들었다가 해제하면서 회원 수를 출력한다. 추가하거나 수정할 멤버는 다음과 같다.

| 멤버 | 하는 일 |
|:-----|:-----|
| `static int numPerson` | 현재 존재하는 `Person` 객체의 수를 저장한다 |
| 생성자 | 객체를 초기화하고 `numPerson`을 1 늘린다 |
| `~Person()` | `numPerson`을 1 줄인다 |
| `show()` | `id`, `weight`, `name` 뒤에 `numPerson`을 출력한다 |
| `static void nPerson()` | `numPerson`만 출력한다 |

*표 3. Q2에서 추가하거나 수정하는 멤버*

### 3.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 이름 공간을 기본으로 쓴다. 생성자는 [실습 2-1]처럼 세 가지로 중복하였다. 매개변수가 없는 생성자는 1, 20.5, `"Grace"`로 초기화하고, 두 번째 생성자는 `id`와 `name`을 받아 `weight`에 20.5를 쓰며, 세 번째 생성자는 세 값을 모두 받아 초기화한다. 세 생성자 모두 객체가 생성될 때마다 `numPerson`을 1 늘리고, 소멸자는 객체가 소멸될 때 1 줄인다.

`show()`는 객체의 세 멤버 변수와 현재 객체 수를 출력하고, static 멤버 함수 `nPerson()`은 현재 객체 수만 출력한다. 클래스 안의 `static int numPerson;`은 선언일 뿐이며, 49행의 `int Person::numPerson = 0;`이 클래스 밖에서 변수를 정의하고 0으로 초기화한다. 이 줄을 지우면 컴파일은 되지만 링크 단계에서 `Person::numPerson`을 찾지 못한다는 오류가 난다([6장 3.1절](../../Lecture-Notes/Ch06_Overloading-and-Static-Members/Concepts_Lecture.ko.md#31-static-멤버-변수)).

`main()`은 기본 생성자로 `grace`를, 세 번째 생성자로 `helen`을 만든다. 이어서 `new Person[2] { {43, "Tera"}, {98, "Hera"} }`로 두 `Person` 객체의 동적 배열을 만든다. 중괄호 안의 `{43, "Tera"}`와 `{98, "Hera"}`가 각 원소의 생성자 인자가 되어 두 번째 생성자가 두 번 호출된다. 동적 배열의 원소를 이렇게 초기화하는 문법은 C++11에서 도입되었으며, `-std=c++98`로 컴파일하면 이 줄에서 오류가 난다([4장 3.3절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#33-동적-객체-배열)). 각 원소의 정보를 `show()`로 출력하고 `nPerson()`으로 현재 객체 수를 확인한 뒤, 배열을 해제하고 다시 객체 수를 확인한다. 프로그램이 끝나면 남은 객체의 소멸자가 호출된다.

다음 세 가지가 출력을 이해하는 데 필요하다.

- **공유되는 하나의 변수:** `numPerson`은 객체마다 따로 있지 않고 클래스에 하나만 있으므로, 어느 객체의 `show()`로 출력해도 같은 값이 나온다.
- **Tera의 출력이 4인 이유:** `new Person[2] {...}`는 두 원소를 모두 생성한 뒤에 주소를 리턴하므로, `p[0].show()`가 실행될 때는 이미 4명이다.
- **클래스 이름으로 호출:** `nPerson()`은 static 멤버 함수이므로 `this`가 없고, 객체 없이 `Person::nPerson()`으로 호출한다. static 멤버 함수는 static 멤버 변수인 `numPerson`에만 접근하므로 문제가 없다([6장 3.3절](../../Lecture-Notes/Ch06_Overloading-and-Static-Members/Concepts_Lecture.ko.md#33-static-멤버-함수)).

코드를 더 견고하게 만들려면 다음 두 가지를 고려할 수 있다.

- **복사 생성자:** 컴파일러가 만드는 디폴트 복사 생성자는 `numPerson`을 늘리지 않지만, 복사된 객체가 소멸할 때 소멸자는 `numPerson`을 줄인다. 실제로 `main()`에 `{ Person copy = grace; }`를 넣어 실행하면 블록이 끝난 뒤의 `nPerson()`이 4가 아니라 3을 출력하고, 마지막 줄도 2가 아니라 1이 된다. 객체 수를 세는 클래스는 `Person(const Person& p) : id(p.id), weight(p.weight), name(p.name) { numPerson++; }`처럼 개수를 늘리는 복사 생성자를 함께 둔다.
- **생성자 하나로 합치기:** 생성자가 셋이면 `numPerson++`을 세 곳에 써야 한다. Q1의 디폴트 매개변수를 갖는 생성자 하나로 바꾸어도 같은 `main()`이 같은 결과를 출력하며, 개수를 늘리는 코드는 한 곳에만 있으면 된다.

### 3.3 실행 결과와 검토

```text
1 20.5 Grace 1
13 32.5 Helen 2
43 20.5 Tera 4
98 20.5 Hera 4
4
2
```

출력은 강의자료의 실행 예시, 제출한 실행 화면과 같다. `delete [] p;`는 원소의 소멸자를 생성의 역순으로 `p[1]`, `p[0]`의 순서로 호출하여 `numPerson`을 4에서 2로 줄이므로 마지막 줄은 2이다. 이후 `main()`이 끝나면 `helen`과 `grace`의 소멸자가 차례로 호출되어 `numPerson`은 0이 되지만, 이 값은 출력되지 않는다. `leaks --atExit`와 `-fsanitize=address,undefined`로 실행해도 오류와 누수가 보고되지 않는다.

## 4. Q3. static 멤버로 이루어진 Random 클래스

### 4.1 요구사항

static 멤버 함수만 가진 `Random` 클래스를 완성하고, 1에서 100 사이의 랜덤 정수 10개, 랜덤 알파벳 10개, 랜덤 실수 10개를 출력하는 `main()`을 완성한다. 실수는 5개씩 두 줄로 출력한다.

| 멤버 함수 | 하는 일 |
|:-----|:-----|
| `seed()` | 현재 시각으로 난수의 시드를 정한다 (몸체가 주어짐) |
| `nextInt(min, max)` | `min` 이상 `max` 이하의 랜덤 정수를 리턴한다. 디폴트 값은 0과 32767이다 |
| `nextAlphabet()` | 대문자 또는 소문자인 랜덤 알파벳 한 글자를 리턴한다 |
| `nextDouble()` | 0 이상 1 미만의 랜덤 실수를 리턴한다 |

*표 4. Q3의 Random 클래스가 가지는 static 멤버 함수*

### 4.2 설계와 해결 방법

입출력, 난수 생성, 시간 함수를 위해 `<iostream>`, `<cstdlib>`, `<ctime>`을 포함한다. 주어진 `seed()`는 클래스 안에서 정의되어 있고, 나머지 세 함수는 클래스 안에 선언만 두고 클래스 밖에서 정의하였다. 클래스 밖의 정의에는 `static` 키워드와 디폴트 값을 다시 쓰지 않는다.

- **`nextInt(min, max)`:** `rand() % (max - min + 1)`이 0 이상 `max - min` 이하의 값이므로, 여기에 `min`을 더하면 `min` 이상 `max` 이하의 값이 된다. 디폴트 값 0과 32767은 선언에만 있다.
- **`nextAlphabet()`:** `rand() % 2`의 결과가 1이면 `'a' + rand() % 26`으로 소문자를, 0이면 `'A' + rand() % 26`으로 대문자를 만든다. 두 식의 값은 `int`이지만 리턴 타입 `char`로 변환되므로 `cout`은 숫자가 아니라 문자를 출력한다.
- **`nextDouble()`:** `rand()`를 `(double)`로 변환한 뒤 `RAND_MAX`로 나누어 0과 1 사이의 실수를 만든다. 나누기 전에 변환하므로 정수 나눗셈이 아니라 실수 나눗셈이 된다.

`main()`은 먼저 `Random::seed()`를 한 번 호출하여 난수를 초기화한다. 이어서 세 부분에서 각각 `Random::nextInt(1, 100)`으로 1에서 100까지의 정수 10개, `Random::nextAlphabet()`으로 알파벳 10개, `Random::nextDouble()`로 실수 10개를 만들어 출력하며, 실수는 5개씩 두 줄로 나누어 출력한다. 모든 멤버 함수가 static이므로 `Random` 객체를 만들지 않고 클래스 이름으로 호출한다. 안내 문구는 강의자료의 `main()`과 조금 다르다. 강의자료의 `"알파벳을 랜덤하게 10개를 출력합니다"`와 `"랜덤한 실수를 10개를 출력합니다"`를 코드에서는 `"랜덤한 알파벳 10개를 출력합니다"`와 `"랜덤한 실수 10개를 출력합니다"`로 썼다.

시드를 정하는 일을 static 멤버 함수 `seed()`로 분리하였으므로 `main()`의 처음에 한 번만 호출하면 된다. 생성자에서 시드를 정하던 HW1 Q2의 `Random` 클래스는 객체를 만들 때마다 `srand()`가 다시 실행되지만, 이 클래스는 객체를 만들지 않고 시드도 한 번만 정한다. 전역 함수로 둘 수 있는 기능을 클래스의 static 멤버로 묶으면 관련된 함수가 `Random::` 아래에 모여 전역 이름이 줄어든다([6장 3.4절](../../Lecture-Notes/Ch06_Overloading-and-Static-Members/Concepts_Lecture.ko.md#34-활용-사례)).

코드를 더 견고하게 만들려면 다음 두 가지를 고려할 수 있다.

- **`nextDouble()`의 범위:** `rand()`는 0 이상 `RAND_MAX` 이하의 값을 리턴하므로, `rand()`가 `RAND_MAX`를 리턴하면 `(double) rand() / RAND_MAX`는 정확히 1.0이다. 주석은 1보다 작은 실수를 리턴한다고 하지만 실제 범위는 0 이상 1 이하이다. macOS에서는 `RAND_MAX`가 2147483647이므로 한 번의 호출에서 1.0이 나올 확률은 $2^{-31}$이지만, `RAND_MAX`가 32767인 Visual C++에서는 1/32768이다. `rand() / (RAND_MAX + 1.0)`으로 나누면 결과가 항상 1보다 작다. `RAND_MAX + 1`로 쓰면 `RAND_MAX`가 `int`의 최댓값인 macOS에서 정수 오버플로가 되므로 `1.0`을 더해 실수로 계산한다.
- **객체 생성 막기:** 모든 멤버가 static이므로 `Random` 객체를 만들 이유가 없지만, 지금의 클래스로는 `Random r;`처럼 객체를 만들 수 있다. 생성자를 `private`으로 선언하면 객체 생성을 막아 클래스 이름으로만 쓰게 할 수 있다.

### 4.3 실행 결과와 검토

macOS에서 실행한 결과의 한 예는 다음과 같다.

```text
1에서 100까지 랜덤한 정수 10개를 출력합니다
87 54 47 27 17 69 51 41 28 6 
랜덤한 알파벳 10개를 출력합니다
C r j F j s Y s T F 
랜덤한 실수 10개를 출력합니다
0.907427 0.120311 0.0723063 0.252541 0.458961 
0.753511 0.262834 0.444927 0.881017 0.253124 
```

출력 형식은 제출한 실행 화면과 같고, 값은 실행할 때마다 다르다. 각 줄 끝에 공백이 하나 남는 것은 값마다 뒤에 `' '`를 붙이기 때문이다. `cout`은 `double`을 기본적으로 유효 숫자 6자리로 출력하고 끝의 0을 생략하므로, 제출한 실행 화면의 `0.73853`처럼 자릿수가 짧은 값이나 `0.0723063`처럼 소수점 아래가 7자리인 값도 나온다. `leaks --atExit`와 `-fsanitize=address,undefined`로 실행해도 오류와 누수가 보고되지 않는다.

## 5. Q4. static 멤버로 객체 수를 세는 Circle 클래스

### 5.1 요구사항

`Circle` 클래스에 현재 존재하는 `Circle` 객체의 수를 저장하는 `private` static 변수 `count`를 선언하고 클래스 밖에서 초기화한다. 두 생성자는 `count`를 늘리고 소멸자는 줄이며, `show()`는 반지름과 함께 현재 객체 수를 출력한다. 주어진 `main()`은 객체 하나와 원소가 두 개인 동적 배열을 만들고, 배열을 해제하기 전후에 `show()`를 호출한다.

### 5.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 이름 공간을 기본으로 쓴다. `Circle` 클래스는 원을 표현하며, `private` 멤버로 반지름 `radius`와 현재 존재하는 `Circle` 객체의 수를 추적하는 static 변수 `count`를 둔다. `public` 아래에는 두 생성자, 소멸자, `show()`를 둔다.

- **두 생성자:** 매개변수가 없는 생성자는 `radius`를 0으로, 다른 생성자는 받은 값으로 초기화한다. 두 생성자 모두 객체가 생성될 때마다 `count`를 1 늘린다.
- **소멸자:** 클래스 안에 선언만 두고 28~30행에서 클래스 밖에 정의하였다. 객체가 소멸될 때 `count`를 1 줄인다.
- **`show()`:** `Radius: 5, Count: 1` 형식으로 반지름과 현재 객체 수를 출력한다.
- **`count`의 정의:** 31행의 `int Circle::count = 0;`이 static 변수를 정의하고 0으로 초기화한다.

`main()`은 매개변수가 있는 생성자로 `a`를 만들고 `show()`로 출력한다. 이어서 `new Circle[2]`로 두 `Circle` 객체의 동적 배열을 만든다. 초기화 목록이 없으므로 각 원소에 기본 생성자가 호출된다. `for` 문으로 각 원소를 출력하고 `a`를 다시 출력한 뒤, `delete[] p;`로 배열을 해제하고 `p`를 `nullptr`로 설정한다. 마지막으로 `a`를 한 번 더 출력하며, 프로그램이 끝나면 `a`의 소멸자가 호출된다.

`delete[] p;`는 배열의 각 원소에 대해 소멸자를 호출한 뒤 메모리를 반환하므로 `count`가 3에서 1로 줄어든다. `[]` 없이 `delete p;`로 쓰면 배열을 `delete`로 해제하는 것이 되어 정의되지 않은 동작이다. 강의자료의 `main()`은 해제 뒤에 `p = NULL;`을 추가하라고 권하며, 코드는 C++11의 `nullptr`를 썼다. 해제한 포인터에 `nullptr`를 대입하면 그 포인터가 해제된 메모리를 가리키는 댕글링 포인터로 남지 않는다. `NULL`은 정수 0으로 정의될 수 있는 매크로이지만 `nullptr`는 포인터 전용의 값이므로 함수 중복에서 정수로 해석될 위험이 없다([4장 4.2절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#42-댕글링-포인터)).

Q2와 마찬가지로 디폴트 복사 생성자는 `count`를 늘리지 않으므로, `Circle`을 값으로 전달하거나 복사하면 개수가 실제보다 작아진다. 개수를 늘리는 복사 생성자를 함께 두면 이 문제가 없다.

### 5.3 실행 결과와 검토

```text
Radius: 5, Count: 1
Radius: 0, Count: 3
Radius: 0, Count: 3
Radius: 5, Count: 3
Radius: 5, Count: 1
```

출력은 강의자료의 실행 예시, 제출한 실행 화면과 같다. 두 번째와 세 번째 줄의 개수가 3인 것은 `a`와 배열의 두 원소가 모두 존재하기 때문이고, 마지막 줄의 1은 `delete[] p;`가 두 원소를 소멸시킨 뒤의 값이다. `leaks --atExit`와 `-fsanitize=address,undefined`로 실행해도 오류와 누수가 보고되지 않는다.

## 점검 문제

1. **생략할 수 없는 인자:** Q1의 `main()`에 `Person kim(4, 50.0);`을 추가하면 어떻게 되는가?

   <details>
   <summary>정답</summary>

   컴파일 오류가 난다. 인자는 왼쪽 매개변수부터 채워지므로 50.0이 두 번째 매개변수 `string name`에 전달되는데, `double`은 `string`으로 변환할 수 없어 일치하는 생성자가 없다. 무게를 정하려면 `Person kim(4, "Kim", 50.0);`처럼 이름도 넘겨야 한다.

   </details>

2. **배열 원소의 생성 시점:** Q2의 `p[0].show()`가 `43 20.5 Tera 3`이 아니라 `43 20.5 Tera 4`를 출력하는 이유는 무엇인가?

   <details>
   <summary>정답</summary>

   `new Person[2] {...}`는 두 원소를 모두 생성한 뒤에 배열의 주소를 리턴한다. 따라서 `p[0].show()`가 실행되는 시점에는 `grace`, `helen`, `p[0]`, `p[1]`의 네 객체가 이미 존재하고, 공유되는 `numPerson`은 4이다.

   </details>

3. **복사와 개수:** Q2의 61행 `Person::nPerson();` 바로 앞에 `{ Person copy = grace; }`를 넣으면 61행과 64행의 출력은 각각 얼마인가?

   <details>
   <summary>정답</summary>

   4와 2가 아니라 3과 1이다. 디폴트 복사 생성자는 `numPerson`을 늘리지 않으므로 `copy`가 만들어져도 4이고, 블록이 끝나 `copy`의 소멸자가 실행되면 3이 된다. 그래서 61행은 3을 출력하고, 배열을 해제한 뒤의 64행은 1을 출력한다.

   </details>

4. **알파벳의 범위:** Q3의 `nextAlphabet()`이 리턴할 수 있는 문자는 몇 가지인가? `rand() % 2`와 `rand() % 26`이 같은 `rand()` 호출의 결과를 쓰는가?

   <details>
   <summary>정답</summary>

   소문자 26개와 대문자 26개로 52가지이다. 두 식은 `rand()`를 따로 호출하므로 서로 다른 난수를 쓴다. 첫 호출로 대문자와 소문자를 정하고, 두 번째 호출로 26개 중 하나를 고른다.

   </details>

5. **해제하지 않은 배열:** Q4의 `delete[] p;`를 지우고 `main()`을 실행하면 마지막 줄은 무엇을 출력하는가? 두 원소의 메모리는 어떻게 되는가?

   <details>
   <summary>정답</summary>

   배열의 원소가 소멸되지 않으므로 `count`는 3에 머물고 마지막 줄은 `Radius: 5, Count: 3`이다. 두 원소의 소멸자가 호출되지 않고 메모리도 반환되지 않으며, 이어서 `p = nullptr;`로 배열의 주소를 잃으므로 프로그램 안에서는 더 이상 해제할 방법이 없는 메모리 누수가 된다.

   </details>
