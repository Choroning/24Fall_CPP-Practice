## 2. Q1. 동적으로 생성한 Complex 객체

### 2.1 요구사항

기본 생성자, 매개변수 2개 생성자, set 함수, 출력 함수 `pCom()`을 갖춘 복소수 클래스 `Complex`를 정의하고, 객체 두 개를 동적으로 생성하여 포인터 `a`, `b`로 다룬다. 멤버 변수와 생성자, 멤버 함수의 매개변수 이름을 모두 `real`, `image`로 같게 써야 한다. `main()` 뼈대의 각 주석에 대응하는 코드는 다음과 같다.

| `main()` 뼈대의 주석 | 대응하는 코드 |
|:-----|:-----|
| 초기값 정보 없이 첫 번째 동적 객체를 생성하여 포인터 `a`로 관리 | `Complex* a = new Complex;` |
| 초기값 정보 없이 두 번째 동적 객체를 생성하여 포인터 `b`로 관리 | `Complex* b = new Complex;` |
| 포인터 `a`, `b`로 관리되는 동적 객체의 정보 출력 | `a->pCom();`, `b->pCom();` |
| 첫 번째 객체의 `real`을 4로 업데이트 | `(*a).setReal(4);` |
| 두 번째 객체의 `image`를 9로 업데이트 | `(*b).setImage(9);` |
| 두 동적 객체의 정보 출력 | `(*a).pCom();`, `(*b).pCom();` |
| 동적 메모리 해제 | `delete a;`, `delete b;` (각각 뒤에 `nullptr` 대입) |

*표 2. Q1의 `main()` 뼈대와 대응하는 코드*

### 2.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Complex` 클래스는 복소수를 표현하며, 접근 지정자 없이 선언한 실수부 `real`과 허수부 `image`는 `private` 멤버이므로 클래스 밖에서 직접 접근할 수 없다. `public` 아래에는 두 생성자와 `setReal()`, `setImage()`, `pCom()`을 클래스 안에서 선언과 동시에 정의했다.

- **기본 생성자:** `real = image = 1;`로 두 멤버를 1로 초기화한다.
- **매개변수 2개 생성자:** `this->real = real;`, `this->image = image;`로 받은 두 값을 멤버에 대입한다.
- **`setReal()`, `setImage()`:** 같은 방식으로 `this->`를 붙여 멤버를 받은 값으로 바꾼다.
- **`pCom()`:** `real << " + " << image << "i\n"`으로 복소수를 `a + bi` 형태로 출력한다.

매개변수의 이름을 멤버와 같게 쓰라는 조건 때문에 `this`가 필요하다. 멤버 함수 안에서 매개변수 `real`은 같은 이름의 멤버를 가리므로, `real`이라고만 쓰면 매개변수를 뜻한다. `this`는 멤버 함수가 호출된 객체의 주소를 가진 포인터이므로 `this->real`은 그 객체의 멤버 `real`을 가리킨다([4장 1.2절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#12-this-포인터)). `this->` 없이 `real = real;`이라고 쓰면 매개변수를 자기 자신에 대입하는 문장이 되어 멤버는 바뀌지 않는다. Clang은 이 문장에 `explicitly assigning value of variable of type 'int' to itself` 경고(`-Wself-assign`)를 내며, 이때 `setReal(4)`를 호출해도 `1 + 1i`가 출력된다.

`main()`은 `new Complex`로 힙에 `Complex` 객체를 만들고 그 주소를 포인터 `a`에 저장한다. 괄호와 인자 없이 쓴 `new Complex`는 기본 생성자를 호출하므로 두 객체 모두 (1, 1)에서 시작한다([4장 2.2절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#22-동적-객체)). 처음에는 화살표 연산자로 `a->pCom()`, `b->pCom()`을 호출하여 초기 상태를 출력하고, 구분선을 출력한 뒤 `(*a).setReal(4)`와 `(*b).setImage(9)`로 포인터를 역참조하여 값을 바꾼다. `(*a).setReal(4)`는 `a->setReal(4)`와 같은 호출이다. 바뀐 값을 `(*a).pCom()`, `(*b).pCom()`으로 다시 출력한 뒤, `delete a;`와 `delete b;`로 두 객체를 반환하고 각 포인터에 `nullptr`를 대입한다.

다음 두 가지는 이 설계의 성질이다.

- **쓰이지 않는 생성자:** 매개변수 2개 생성자는 이 `main()`에서 호출되지 않는다. `new Complex(2, 3)`처럼 인자를 주어 동적 객체를 만들면 이 생성자가 호출되어 `2 + 3i`인 객체가 생긴다.
- **`delete` 뒤의 `nullptr`:** `delete`는 포인터가 가리키는 객체를 반환할 뿐 포인터 변수의 값은 바꾸지 않으므로, 반환한 뒤의 `a`와 `b`는 댕글링 포인터가 된다. 이 프로그램은 그 뒤에 포인터를 쓰지 않아 출력에는 영향이 없지만, `nullptr`를 대입해 두면 실수로 다시 `delete a;`를 실행해도 널 포인터에 대한 `delete`는 아무 일도 하지 않으므로 이중 해제가 일어나지 않는다([4장 4.2절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#42-댕글링-포인터)).

### 2.3 실행 결과와 검토

```text
1 + 1i
1 + 1i
---------------
4 + 1i
1 + 9i
```

첫 두 줄은 기본 생성자가 만든 초기 상태이고, 마지막 두 줄은 첫 번째 객체의 실수부와 두 번째 객체의 허수부가 바뀐 결과이다. `leaks --atExit`로 실행하면 누수가 없어 두 객체가 모두 반환되었음을 확인할 수 있다.

## 3. Q2. 회원 정보를 관리하는 Member 클래스

### 3.1 요구사항

이름 `name`(`string`), 아이디 `id`(`string`), 나이 `age`(`int`)를 `private` 멤버로 갖는 `Member` 클래스를 구현하고, 두 회원 객체를 만들어 정보를 출력하고 수정한다. 클래스는 다음 멤버를 갖춘다.

| 멤버 | 하는 일 |
|:-----|:-----|
| `Member()` | 멤버를 `"noname"`, `"none"`, 0으로 초기화한다 |
| `Member(string name, string id, int age)` | 받은 세 값으로 `name`, `id`, `age`를 초기화한다 |
| `setName()`, `setId()`, `setAge()` | 각 멤버를 받은 값으로 바꾼다 |
| `getName()`, `getId()`, `getAge()` | 각 멤버의 값을 리턴한다 |
| `printM()` | 세 멤버를 쉼표로 구분하여 한 줄에 출력한다 |

*표 3. Q2의 Member 클래스가 갖추는 멤버*

### 3.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Member` 클래스는 회원 한 명의 정보를 표현하며, 접근 지정자 앞에 선언한 `name`, `id`, `age`는 `private` 멤버이다. 아이디는 학번처럼 계산에 쓰지 않는 번호이므로 문제의 조건대로 `string`으로 저장한다.

- **기본 생성자:** 몸체에서 `name`에 `"noname"`, `id`에 `"none"`, `age`에 0을 대입한다.
- **매개변수 3개 생성자:** 매개변수 이름이 멤버와 같으므로 `this->name = name;`처럼 `this->`로 멤버를 가리켜 대입한다.
- **set 함수:** 세 멤버마다 하나씩 두며, 역시 `this->`로 멤버를 가리킨다.
- **get 함수:** 세 멤버의 값을 리턴한다. 이 `main()`에서는 호출되지 않지만 문제의 요구사항이다.
- **`printM()`:** `name, id, age` 형식으로 출력하고 줄을 바꾼다.

`main()`은 기본 생성자로 `Kim`을, 매개변수 3개 생성자로 `Lee`를 `{"Lee Hi", "2016001", 22}`의 값으로 만들고, 두 객체의 `printM()`을 호출하여 초기 상태를 출력한다. 이어서 `Kim.setName("Kim Haha")`, `Kim.setId("2016020")`, `Kim.setAge(29)`로 `Kim`의 정보를 바꾸고, 바뀐 정보를 다시 `printM()`으로 출력한다.

코드를 더 견고하게 만들려면 다음 세 가지를 고려할 수 있다.

- **`<string>`의 포함:** 코드는 `string`을 쓰면서 `<string>`을 포함하지 않는다. 이 코드가 Apple clang(libc++)에서 컴파일되는 것은 이 라이브러리의 `<iostream>`이 내부에서 `<string>`의 내용을 간접적으로 포함하기 때문이며, C++ 표준은 이를 보장하지 않는다. 다른 표준 라이브러리 구현에서도 컴파일되게 하려면 쓰는 이름의 헤더를 직접 포함해야 한다.
- **멤버 초기화 리스트:** 기본 생성자는 멤버를 먼저 만든 뒤 몸체에서 값을 대입한다. `Member() : name("noname"), id("none"), age(0) {}`처럼 멤버 초기화 리스트를 쓰면 멤버가 만들어지는 시점에 바로 초기화된다([3장 4.4절](../../Lecture-Notes/Ch03_Classes-and-Objects/Concepts_Lecture.ko.md#44-멤버-변수의-초기화-방법)).
- **문자열 매개변수의 복사:** 생성자와 set 함수는 `string`을 값으로 받으므로, `string` 객체를 인자로 주면 매개변수로 한 번 복사된다. 5장의 `const string&` 매개변수로 받으면 이 복사 없이 원본을 읽을 수 있다([5장 3.2절](../../Lecture-Notes/Ch05_Functions-and-Copy-Control/Concepts_Lecture.ko.md#32-참조-매개변수)).

### 3.3 실행 결과와 검토

```text
noname, none, 0
Lee Hi, 2016001, 22
Kim Haha, 2016020, 29
```

첫 줄은 기본 생성자의 초기값, 둘째 줄은 매개변수 3개 생성자의 초기값, 셋째 줄은 set 함수로 바꾼 `Kim`의 정보이다.

## 4. Q3. 동적 정수 배열로 구하는 평균

### 4.1 요구사항

정수 5개를 저장할 배열을 동적으로 할당받고, 정수 5개를 입력받아 평균을 구하여 출력한 뒤 배열을 반환하는 `main()`을 작성한다.

### 4.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `main()`은 입력값을 누적할 정수 변수 `ave`를 0으로 초기화하고, `int* p = new int[5];`로 `int` 5개의 공간을 힙에 할당한다([4장 2.3절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#23-동적-배열)). 프롬프트를 출력한 뒤 `for` 문으로 다섯 번 반복하며 `cin >> p[i];`로 입력값을 배열에 저장하고, 같은 값을 `ave`에 더한다. `p[i]`는 `*(p + i)`와 같은 뜻으로, 포인터 연산으로 동적 배열의 `i`번째 원소에 접근한다.

입력이 끝나면 `ave / 5.0`으로 평균을 계산하여 출력한다. 나누는 수 `5.0`이 `double`이므로 `int`인 `ave`가 `double`로 변환된 뒤 실수 나눗셈이 수행된다. `ave / 5`라고 쓰면 두 피연산자가 모두 정수이므로 정수 나눗셈이 되어 몫만 남고, 입력 `1 2 4 5 10`에서 4.4가 아닌 4가 출력된다. 마지막으로 `delete [] p;`로 배열을 반환하고 `p = nullptr;`로 포인터를 널 포인터로 만든다.

다음 세 가지는 코드를 읽을 때 짚어 둘 점이다.

- **변수 이름:** `ave`는 평균이 아니라 입력값의 합을 저장하고, 평균은 출력할 때 계산된다. 저장하는 값에 맞게 `sum`이라고 이름 짓는 편이 코드를 읽기 쉽다.
- **배열의 역할:** 평균만 구하려면 배열 없이 입력받는 즉시 더해도 되지만, 문제는 동적 배열을 연습하도록 5개의 공간을 할당하게 한다. 입력값이 배열에 남아 있으므로 평균보다 큰 수를 세는 것처럼 입력을 다시 쓰는 처리로 확장할 수 있다.
- **출력 형식:** `cout`은 기본 설정에서 실수를 유효 숫자 6자리까지 출력하고 뒤쪽의 0을 생략한다. 따라서 평균이 정수이면 `1 2 3 4 5`의 평균이 `3`으로 출력되듯이 소수점 없이 나온다.

### 4.3 실행 결과와 검토

`1 2 4 5 10`을 입력하면 다음과 같이 출력된다.

```text
정수 5개 입력 >> 1 2 4 5 10
평균 4.4
```

입력값의 합 22를 5.0으로 나눈 4.4가 출력된다. 입력을 파이프로 넣으면 입력한 값이 화면에 나타나지 않으므로 `정수 5개 입력 >> 평균 4.4`처럼 프롬프트와 결과가 한 줄에 이어진다.

## 5. Q4. Circle 객체의 동적 배열

### 5.1 요구사항

주어진 `Circle` 클래스를 그대로 쓰고, 원의 개수를 입력받아 그 크기의 `Circle` 객체 배열을 동적으로 생성한다. 각 원의 반지름을 입력받아 면적이 100 이상인 원의 개수를 출력하고, 마지막으로 동적 메모리를 해제한다.

### 5.2 설계와 해결 방법

입출력을 위해 `<iostream>`을 포함하고, `using namespace std;`로 표준 네임스페이스를 기본으로 쓴다. `Circle` 클래스는 원을 표현하며, `private` 멤버 `radius`와 `public` 멤버 함수 `setRadius()`, `getArea()`의 원형만 클래스 안에 두고 몸체는 클래스 밖에서 정의한다. `setRadius()`는 매개변수 이름이 멤버와 같으므로 `this->radius = radius;`로 멤버에 대입하고, `getArea()`는 `3.14 * radius * radius`를 리턴한다.

`main()`은 `Circle` 포인터 `p`, 원의 개수 `size`, 면적이 100 이상인 원의 개수를 셀 `count`(0으로 초기화)를 선언한다. 원의 개수를 입력받은 뒤 `p = new Circle [size];`로 `size`개의 `Circle` 객체 배열을 힙에 생성한다. `Circle`에는 생성자가 하나도 선언되어 있지 않으므로 컴파일러가 제공하는 기본 생성자가 원소마다 호출되며, 이 생성자는 `radius`를 초기화하지 않는다([4장 3.3절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#33-동적-객체-배열)). `for` 문은 원마다 반지름을 임시 변수 `temp`에 입력받아 `p[i].setRadius(temp)`로 설정하고, 곧바로 `p[i].getArea()`가 100 이상이면 `count`를 1 늘린다. 반복이 끝나면 `count`를 넣은 결과 문장을 출력한다.

> **주의:** 뼈대의 마지막 주석은 동적 메모리 해제를 요구하지만 코드에는 `delete [] p;`가 없다. macOS의 `leaks --atExit`로 실행하면 누수 1개, 32바이트가 보고된다. `sizeof(Circle)`이 4이므로 객체 5개에 20바이트를 요청하고, 할당자가 이를 32바이트 블록으로 잡기 때문이다. 프로그램이 끝나면 운영체제가 메모리를 회수하므로 이 프로그램의 결과는 달라지지 않지만, 같은 코드가 반복해서 호출되는 함수 안에 있으면 누수가 쌓여 쓸 수 있는 메모리가 줄어든다([4장 4.1절](../../Lecture-Notes/Ch04_Pointers-Arrays-and-Dynamic-Memory/Concepts_Lecture.ko.md#41-메모리-누수)). 출력문 뒤에 `delete [] p;`와 `p = nullptr;`를 두면 누수가 보고되지 않는다.

다음 두 가지도 짚을 수 있다.

- **조건과 출력 문구:** 조건 `p[i].getArea() >= 100`은 문제의 "100 이상"을 따르지만, 출력 문구는 문제의 실행 예시처럼 "100보다 큰"이라고 쓴다. 반지름이 정수이면 면적은 반지름 5에서 78.5, 6에서 113.04이므로 정확히 100이 되는 경우가 없어 두 조건의 결과는 같다. 그래도 문구는 조건에 맞게 "100 이상인"으로 쓰는 편이 정확하다.
- **잘못된 개수 입력:** 0을 입력하면 반복이 한 번도 실행되지 않아 `0개`가 출력된다. 음수를 입력하면 `new Circle [size]`가 메모리를 할당하지 못해 예외(이 환경에서는 `std::bad_alloc`)가 발생하고, 이를 처리하지 않았으므로 프로그램이 비정상 종료된다.

### 5.3 실행 결과와 검토

원의 개수로 5를, 반지름으로 3, 7, 2, 9, 1을 입력하면 다음과 같이 출력된다.

```text
원의 개수 >> 5
원 1의 반지름 >> 3
원 2의 반지름 >> 7
원 3의 반지름 >> 2
원 4의 반지름 >> 9
원 5의 반지름 >> 1
면적이 100보다 큰 원은 2개 입니다.
```

다섯 원의 면적은 28.26, 153.86, 12.56, 254.34, 3.14이므로 100 이상인 원은 반지름이 7과 9인 두 개이다. 입력을 파이프로 넣으면 입력한 값이 화면에 나타나지 않으므로 프롬프트들이 한 줄에 이어진다.

| 동적 객체 | `new Complex`는 힙에 객체를 만들고 기본 생성자를 호출하며, `delete`로 반환한다. |

## 점검 문제

1. **`this`의 생략:** Q1의 `setReal()`을 `void setReal(int real) { real = real; }`로 바꾸고 프로그램을 실행하면 넷째 줄은 무엇이 출력되는가?

   <details>
   <summary>정답</summary>

   `real = real;`은 매개변수를 자기 자신에 대입하므로 멤버는 1에서 바뀌지 않고, 넷째 줄은 `4 + 1i`가 아니라 `1 + 1i`가 출력된다. Clang은 이 문장에 `-Wself-assign` 경고를 낸다.

   </details>

2. **인자를 준 동적 생성:** Q1의 `main()`에서 `Complex* c = new Complex(2, 3);`을 실행하고 `c->pCom();`을 호출하면 무엇이 출력되며, 어느 생성자가 호출되는가?

   <details>
   <summary>정답</summary>

   매개변수 2개 생성자가 호출되어 `this->real`이 2, `this->image`가 3이 되므로 `2 + 3i`가 출력된다. 사용이 끝나면 `delete c;`로 반환해야 한다.

   </details>

3. **나눗셈의 종류:** Q3에 `1 2 3 4 6`을 입력하면 무엇이 출력되는가? 출력문의 `5.0`을 `5`로 바꾸면 어떻게 되는가?

   <details>
   <summary>정답</summary>

   합이 16이므로 `16 / 5.0`인 `평균 3.2`가 출력된다. `5`로 바꾸면 정수 나눗셈 `16 / 5`의 몫인 `평균 3`이 출력된다.

   </details>

4. **`delete`와 `delete []`:** Q4에 누수를 막으려고 `delete p;`를 추가하면 올바른가?

   <details>
   <summary>정답</summary>

   올바르지 않다. `new Circle [size]`처럼 `new[]`로 할당한 메모리는 `delete []`로 반환해야 하며, `delete`로 반환하면 정의되지 않은 동작이다. `delete [] p;`를 써야 한다.

   </details>

5. **경계값:** Q4에서 원의 개수로 3을, 반지름으로 5, 6, 10을 입력하면 몇 개가 세어지는가?

   <details>
   <summary>정답</summary>

   면적은 78.5, 113.04, 314이므로 100 이상인 원은 반지름이 6과 10인 두 개이고, `면적이 100보다 큰 원은 2개 입니다.`가 출력된다.

   </details>
